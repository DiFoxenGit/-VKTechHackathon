# Архитектура

## Границы слоёв

1. **HTTP** (`designer/app.py`): загрузки, валидация, CORS, общий токен, ресурсы, задачи, конфликты версий. Схемы запросов в `models.py`.
2. **Хранение** (`storage.py`): SQLite с атомарными записями JSON, исходные PPTX и артефакты на диске. UUID не зависит от имени файла. SQL параметризован; пользовательские имена не становятся путями.
3. **Парсинг** (`parsing.py`): ZIP/XML PPTX через python-pptx, тема/мастера/макеты, шрифты, размеры, цвета, прямоугольники объектов. Дополнительно выводится геометрия шаблона: рабочая область (`safe_area`), внешние поля (`margins`), вертикальные направляющие и — для каждого паттерна — фон слайда и рамки сохраняемого брендинга. Никаких вызовов модели. Проверяется размер распакованного архива.
4. **Планирование** (`generation.py`): бриф + материалы → валидированная `Outline`. HTTP-клиент OpenAI-совместимого провайдера. Промпты, манифест и версии в `designer/prompts`; снимок с хешами записывается в задачу и презентацию.
5. **Верстка** (`layout.py`): общая структура + шаблон → три JSON-модели геометрии. Поля, направляющие и типографика берутся из разобранного шаблона, а не из констант; блоки на слайде выравниваются по общему левому краю, а заголовок обходит логотипы и колонтитулы шаблона. Цвет текста выбирается из палитры по контрасту к фону слайда один раз, и верстка, экспорт и аудит используют это решение. Координаты в пунктах, 72 pt = 1 inch. Сохраняются индексы исходных паттернов и макетов.
6. **Аудит** (`audit.py`): детерминированные проверки геометрии/контента и отдельно контекстуальный вызов. Исправления применяются только по выбранным ID. После изменения пересчитываются проверки; неустранённая проблема остаётся в отчёте.
7. **Экспорт** (`exporting.py`): исходный PPTX с сохранёнными мастерами, макетами и рисунками; новые текстовые рамки, таблицы, charts, фигуры и заметки — нативные объекты. Какие шапки шаблона переживают клонирование, решает один предикат `preserved_shape`, общий для экспорта и аудита. После записи каждой ревизии `verify_pptx` открывает результат и подтверждает, что слайды состоят из редактируемых объектов. LibreOffice рендерит этот PPTX в PDF; PyMuPDF преобразует страницы в SVG для самостоятельного HTML.

## Пайплайн

`template + content → outline → classic/split/focus → audit → native PPTX → user fixes → new revision → PDF/HTML`

Одна Outline применяется ко всем трём вариантам без изменения фактов. Ось различий: положение текстовых и визуальных блоков, вертикальная или двухколоночная композиция, размер области акцента. Выбор исходного паттерна также может отличаться. Используются одна палитра, гарнитура и типографическая шкала исходного файла. Это эвристическая адаптация; не формальное доказательство соответствия всей дизайн-системе.

## Выполнение

В процессе допускаются две одновременные генерации, максимум 20 активных/ожидающих задач. Все обращения к модели асинхронные, тяжёлый PPTX экспорт выполняется в потоке. Генерация имеет таймаут 300 секунд после входа в слот; очередь не включена. Синхронный экспорт в потоке не может быть принудительно остановлен Python-таймаутом, поэтому этот предел не является жесткой гарантией времени CPU-работы.

Задачи persistent по статусам, но не resumable: при перезапуске незавершённые помечаются ошибкой. Production с несколькими процессами потребует внешней очереди и распределённых блокировок. Текущий compose явно запускает один worker.

Ревизии неизменяемы на диске (`r1.pptx`, `r2.pptx`…), запись новой ревизии происходит после успешного экспорта. `revision` в PATCH/fixes обеспечивает оптимистическую блокировку (409 при конфликте). Для PDF/HTML используется отдельный временный профиль LibreOffice; готовые результаты кешируются по ревизии.

## Связь с Presenton

Модуль находится в Python-сервере исходного репозитория, но не импортирует исходный `api.main`, его authentication/middleware, LLM registry и экспорт через Next.js. Это осознанная граница: новый фронтенд может работать отдельно, а модель и серверный экспорт ограничены нуждами ТЗ. Старые `/api/v1/ppt/*` не входят в новый сервис. Для текущего фронтенда нужно использовать контракт `docs/API.md`.
