# Слайд — фронтенд дизайнера презентаций

Интерактивный прототип для кейса VK Tech, ЛЦТ 2026. React 19, TypeScript, Vite. Интерфейс на русском языке, адаптирован для настольного экрана и небольших окон.

Основной сценарий: **описать идею → нажать «Создать презентацию» → получить готовую презентацию**. По умолчанию используются 10 слайдов и VK Tech. Шаблоны, аудитория и объём скрыты в «Настроить». Структура, три варианта дизайна и проверка доступны в меню редактора и не являются обязательными шагами.

## Запуск

Требуется Node.js 22.12+ и npm.

```bash
npm ci
npm run dev
```

Откройте адрес, который покажет Vite (обычно http://127.0.0.1:5173).

```bash
npm run build
npm run preview
```

`npm run check` проверяет TypeScript, статусы и отмену API-операций, ошибки, прогресс передачи и восстановление сохранённых проектов. Проверки используют имитацию API и не запускают серверную генерацию.

Браузерные регрессии запускаются через Playwright CLI в отдельных сессиях. При запущенном Vite (подставьте его адрес) выполните для каждой пары:

```bash
npx --yes --package @playwright/cli playwright-cli --session qa-ui open http://127.0.0.1:5173
npx --yes --package @playwright/cli playwright-cli --session qa-ui run-code --filename scripts/qa-ui.cjs
npx --yes --package @playwright/cli playwright-cli --session qa-editor open http://127.0.0.1:5173
npx --yes --package @playwright/cli playwright-cli --session qa-editor run-code --filename scripts/qa-editor.cjs
npx --yes --package @playwright/cli playwright-cli --session qa-edge open http://127.0.0.1:5173
npx --yes --package @playwright/cli playwright-cli --session qa-edge run-code --filename scripts/qa-edge.cjs
```

Сценарии изолированы тестовыми данными и ответами API: создание и отмена, ошибки и повтор, редактирование и порядок слайдов, оформление, аудит, сохранение после перезагрузки, поиск и удаление, экспорт, долгое ожидание, загрузка шаблона и адаптивность. Они также работают при открытии production preview под `/presentations/`.

Сборка находится в `dist/`. Для генерации и загрузки файлов нужен запущенный backend. В режиме разработки Vite проксирует `/presentations/api/v1` на `http://127.0.0.1:8000/api/v1`; другой адрес backend задаётся через `VITE_PRESENTATIONS_API_BASE_URL` в `.env.local`. Это позволяет работать без настройки CORS. Шрифты поставляются с приложением, API-ключи во фронтенде не нужны.

## Что работает

- Бриф, готовые примеры, аудитория, цель и количество слайдов.
- Видимые этапы генерации, настоящий процент сервера, таймер и сообщение при долгом ожидании. Ожидание можно прекратить, сохранив бриф; серверное задание при этом может продолжиться.
- Прогресс передачи материалов и шаблонов, отдельный этап обработки, прогресс скачивания и повтор после ошибки.
- Загрузка материалов TXT/MD/CSV/JSON/DOCX/PPTX/PDF до 50 МБ, включая перетаскивание файла.
- Библиотека трёх шаблонов с реальными метаданными из предоставленного архива.
- Загрузка PPTX-шаблонов до 50 МБ на production backend с извлечением палитры, шрифтов и макетов.
- Редактирование структуры: заголовки, тезисы, добавление, удаление и изменение порядка.
- Возврат последнего удалённого слайда и переключение слайдов стрелками в просмотре.
- Три оформления одинакового содержания, миниатюры, редактор текста и полноэкранный просмотр слайдов.
- Проверки пустого содержимого, длинного текста, повторов и лишних пробелов.
- Экспорт серверных PPTX/PDF/HTML с использованием выбранного PPTX-шаблона.
- Библиотека презентаций с поиском, удалением и сохранением в localStorage. Каждая презентация хранит свой исходный бриф.
- Автосохранение после паузы ввода и перед уходом со страницы, видимый статус сохранения, восстановление совместимых старых данных.
- Проверка формата/размера файлов, сообщения об ошибках, доступные подписи кнопок, управление модальными окнами с клавиатуры.

## Работа с production API

Фронтенд использует backend под `/presentations`: загружает шаблоны и материалы, отправляет генерацию через `POST /api/v1/generations`, опрашивает job до завершения и скачивает серверные PPTX/PDF/HTML. При текущем отключённом LLM outline готовится детерминированно во фронтенде и передаётся серверу явно, поэтому генерация через шаблон остаётся доступной.

Результаты дополнительно кэшируются в `localStorage`, чтобы можно было продолжить работу в этом браузере. Серверные записи не удаляются кнопкой удаления локальной копии. Для точного отображения PPTX шрифт шаблона должен быть установлен на устройстве получателя.

Во время генерации можно перейти на другой экран: результат сохранится в библиотеке, а уведомление предложит его открыть. Загрузки отменяются при открытии другого проекта, чтобы материалы не попадали в чужой бриф. Одновременно запускается только одна операция.

После редактирования экспорт формируется в браузере с последними правками. Для локального PDF открывается окно печати с выбором «Сохранить как PDF». Библиотека PPTX и встроенные шрифты автономного HTML подгружаются только при экспорте.

Для серверных PDF и HTML backend должен быть запущен с LibreOffice (например, в штатном Docker-образе). Если конвертер недоступен, интерфейс покажет понятную ошибку и предложит скачать PPTX; локальные экспорты редактора от серверного конвертера не зависят.

## Интеграция

Точка интеграции: `src/services/presentationService.ts`. Здесь находятся типизированные вызовы шаблонов, контент-паков, генерации/job и серверного экспорта. Методы принимают `ServiceOptions` с `signal` и `onProgress`; проценты отражают измеренные байты или `job.progress`, а не расчёт по времени. Запросы ограничены таймаутами, отмена останавливает запросы и опрос статуса.

В production базовый адрес задаётся `VITE_PRESENTATIONS_API_BASE_URL`; по умолчанию используется `/presentations/api/v1`, поэтому сборка работает под `/presentations/`. Перед production-сборкой убедитесь, что локальная переменная не указывает на localhost.

## Структура проекта

```text
src/
  App.tsx                         экраны и пользовательские действия
  styles.css                      дизайн и адаптивная вёрстка
  simplified.css                  простой главный экран и компактная навигация
  ux.css                          состояния операций, доступность и адаптивность
  components/OperationProgress.tsx этапы, измеренный прогресс и отмена
  storage.ts                      проверка и восстановление сохранённых данных
  engine.ts                       локальная сборка, PPTX, аудит, экспорт
  types.ts                        доменные типы
  services/presentationService.ts граница интеграции API
  main.tsx                        запуск и локальные шрифты
public/favicon.svg
```

## Материалы кейса

Метаданные библиотеки прочитаны из `Датасет.zip`: VK Tech (54 слайда / 39 макетов), VK WorkSpace (29 / 15), VK Education (55 / 30). В предоставленном архиве нет отдельного контент-пакета. Тексты внутри шаблонов не использованы как бизнес-факты.

PDF с заданием использован для определения пользовательского сценария. Шаблон презентации ЛЦТ относится к оформлению питча, а не к дизайну интерфейса. Исходные файлы не изменены и не включены в репозиторий.
