# Модели

## Требование ТЗ и как оно выполнено

Разрешены модели с открытыми весами до 35B под лицензией Apache 2.0 или MIT. Модель не зашита в код: сервис ходит в любой OpenAI-совместимый эндпоинт, заданный переменными окружения. Скрытых вызовов закрытых моделей нет — весь трафик идёт через `designer/generation.py`, где адрес и идентификатор читаются из окружения.

| Роль | Переменные | Что делает |
|---|---|---|
| Текстовая модель | `DESIGNER_LLM_BASE_URL`, `DESIGNER_LLM_MODEL`, `DESIGNER_LLM_API_KEY` | план колоды, сокращение перегруженных слайдов, контекстуальный аудит |
| Мультимодальная | `DESIGNER_VLM_MODEL`, `DESIGNER_VLM_BASE_URL`, `DESIGNER_VLM_API_KEY` | аудит по картинке слайда; подпись иконок и иллюстраций шаблона (агент `assets`), чтобы подбирать их к тезисам. Без переменных оба шага выключены, а иконки берутся из встроенного набора |

`DESIGNER_VLM_BASE_URL` и `DESIGNER_VLM_API_KEY` необязательны: без них берутся значения текстовой модели.

## Проверенная конфигурация

Отборочный этап проходил на Yandex AI Studio — это тот же OpenAI-совместимый интерфейс:

```bash
DESIGNER_LLM_BASE_URL=https://ai.api.cloud.yandex.net/v1
DESIGNER_LLM_MODEL=gpt://<folder_id>/gpt-oss-20b
DESIGNER_LLM_API_KEY=<API-ключ сервисного аккаунта>
DESIGNER_VLM_MODEL=gpt://<folder_id>/qwen3.6-35b-a3b
```

| Модель в AI Studio | Веса на Hugging Face | Лицензия | Размер |
|---|---|---|---|
| `gpt-oss-20b` | [openai/gpt-oss-20b](https://huggingface.co/openai/gpt-oss-20b) | Apache 2.0 | 20B |
| `qwen3.6-35b-a3b` | [Qwen/Qwen3.6-35B-A3B](https://huggingface.co/Qwen/Qwen3.6-35B-A3B) | Apache 2.0 | MoE, 3B активных параметров |

Лицензия у обеих карточек — `apache-2.0`, то есть требование ТЗ выполнено. По размеру:
у `gpt-oss-20b` 20B, у мультимодальной модели активных параметров 3B, но всего в MoE
карточка Hugging Face показывает 36B. Если жюри считает предел в 35B по общему числу
параметров, мультимодальную модель нужно заменить — например, на
[Qwen/Qwen3.6-27B](https://huggingface.co/Qwen/Qwen3.6-27B) той же лицензии. Аудит по
картинке при этом не ломается: модель задаётся переменной `DESIGNER_VLM_MODEL`.

Ключ выдаётся сервисному аккаунту с ролью `ai.languageModels.user`, область действия — `yc.ai.foundationModels.execute`. Ключ остаётся на сервере и в браузер не попадает.

Альтернатива для self-hosted инференса: [Qwen3-32B](https://huggingface.co/Qwen/Qwen3-32B) через vLLM или Ollama — карточка модели содержит инструкции запуска OpenAI-совместимого сервера. После предварительного заполнения профилей переключение на финале выполняется одной строкой `DESIGNER_LLM_PROVIDER=vk` в `.env` и пересозданием backend.

## Работа со слабой моделью

Открытые модели на 20B ошибаются заметно чаще закрытых, и конвейер рассчитан именно на это:

- **Ответ валидируется, а не принимается на веру**: число слайдов, ссылки только на загруженные материалы, единый язык подписей внутри визуализации, запрет на числа, которых нет в источниках, запрет на дубли заголовков.
- **Повтор с причиной**: при провале валидации модель получает конкретную претензию и переписывает ответ (`DESIGNER_LLM_ATTEMPTS`, по умолчанию 3).
- **Допуск на последней попытке**: если модель упорно отдаёт меньше слайдов, принимается не менее 60 % запрошенного — колода из шести слайдов лучше, чем ошибка 502.
- **Детерминированный запасной путь**: сокращение текста по вместимости работает и без модели.
- **Контекст ограничен** 24 000 символов отобранных по релевантности фрагментов (`DESIGNER_CONTEXT_CHARS`): длинный контекст такие модели держат плохо.

Вёрстка, выбор паттерна, типографика, цвета и детерминированный аудит модель не трогает вовсе — это код. Поэтому качество слайда не падает вместе с качеством модели.

## Промпты и версии

Промпты лежат отдельными файлами в `designer/prompts/`, манифест хранит версию воркфлоу и changelog с причиной каждого изменения. В задачу и презентацию записывается снимок: версия воркфлоу, sha256 каждого промпта и идентификатор модели.

## Ресурсы

При внешнем инференсе бэкенду GPU не нужен. Рабочая конфигурация: 2 vCPU / 2 ГБ RAM + swap (LibreOffice и сборка фронтенда иначе падают по OOM). Локальная 32B-модель — отдельная машина: веса занимают около 64 ГБ в 16-bit или 16 ГБ в 4-bit, без KV cache.

## Воспроизводимость и ограничения

Temperature 0.2, ответ валидируется как JSON. Побитовой воспроизводимости генерации никто не обещает: для полностью детерминированной проверки вёрстки передайте сохранённый `outline` — тогда модель не вызывается вообще.

Размер и лицензию развёрнутой модели проверяет оператор: произвольный model ID провайдера невозможно достоверно проверить программно. Генерация изображений (задание со звёздочкой) не реализована.

## Профиль инференса VK (P3-16)

Подготовлено переключение профилей; **живое подтверждение совместимости VK пока
не выполнено**. Для него нужны выданные организаторами URL, точный API ID модели
«Qwen 3.8 27b» и тестовый ключ. Имя из задания не подставляется автоматически:
API ID, доступный контекст, квоты и поддержка `response_format` должны быть
подтверждены конкретным эндпоинтом. Время менее пяти минут пока не измерено на VK.

Конфигурация `openai` (по умолчанию) сохраняет существующие `DESIGNER_LLM_*`,
в том числе приведённый выше профиль Yandex. Профиль `vk` читает отдельные
`DESIGNER_VK_BASE_URL`, `DESIGNER_VK_MODEL`, `DESIGNER_VK_API_KEY`.
Выбор задаётся `DESIGNER_LLM_PROVIDER=openai|vk`; неполный профиль VK возвращает
503 и не отправляет запросы прежнему провайдеру.

Настройки собраны в [inference.py](backend/designer/inference.py), транспорт —
`ask` в [generation.py](backend/designer/generation.py):
`POST <BASE_URL>/chat/completions`, `Authorization: Bearer <API_KEY>`, поля
`model`, `messages`, `temperature=0.2`, `max_tokens` и по умолчанию
`response_format={"type":"json_object"}`. Ожидается
`choices[0].message.content` (строка или текстовые части); также поддержан
`reasoning_content`. JSON и предметная схема валидируются существующим конвейером.

Для каждого профиля доступны суффиксы `_MAX_TOKENS` (14000), `_TIMEOUT`
(150 секунд на операции HTTP, подключение — 15 секунд), `_JSON_MODE` (1).
Это исходные настройки клиента, **не заявленные лимиты VK**. Если выданный API
не поддерживает `response_format`, после проверки выставить
`DESIGNER_VK_JSON_MODE=0`; локальная валидация JSON сохранится. Автоматического
повтора с изменением контракта нет. Повторы агентов по-прежнему ограничены
`DESIGNER_LLM_ATTEMPTS`, задача сервиса — таймаутом 300 секунд после входа в слот.

VLM использует явные `DESIGNER_VLM_BASE_URL`/`DESIGNER_VLM_API_KEY`, а при их
отсутствии — адрес и ключ выбранного текстового профиля. При сохранении VLM на
Yandex укажите оба значения явно, чтобы после переключения не отправить её ID
в VK. Поддержка изображений текстовой моделью VK не предполагается.
`/health` проверяет наличие выбранной конфигурации, а не доступность провайдера;
в метаданные колоды записываются выбранные профиль и ID модели без ключа.

Проверка: [tools/check_inference.py](tools/check_inference.py) отправляет реальный
запрос выбранной модели и проверяет JSON. С `--service` и `--template-id` также
создаёт задачу без готовой Outline, проверяет три варианта по 12 слайдов,
отсутствие ошибок аудита, открытие PPTX и генерацию менее 300 секунд, сверяет
профиль и модель в метаданных сервиса. Не выводит ключи или тела ошибок провайдера.
Инструкция запуска и отката — [docs/deploy.md](docs/deploy.md#переключение-на-vk).
Контрактные тесты с MockTransport проверяют клиент; они не заменяют прогон VK.
