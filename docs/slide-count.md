# Количество слайдов

Количество видно и изменяется рядом с запросом; существующее поле в окне «Настроить» использует то же состояние. При вводе явной инструкции вроде «из пяти слайдов», «на 5 слайдов» или «a 5-slide presentation» число автоматически переносится в настройки. То же происходит при открытии сохранённого брифа со старым значением по умолчанию.

Распознаются целые значения 1–30 цифрами, распространёнными русскими и английскими числительными. Номера пунктов, «слайд 2», годы и бизнес-показатели не задают объём. Неоднозначные диапазоны не превращаются в точное количество; используется видимое поле. Несколько разных явных количеств и недопустимые значения требуют исправления текста.

Если вручную выбрать другое количество, интерфейс показывает конфликт и предлагает использовать число из запроса. До исправления платная генерация не начинается. Backend независимо сверяет текст и `slide_count` и возвращает HTTP 422 до создания задания. Для прямого API-клиента значения должны совпадать; сервер не изменяет запрос молча. Проверка распространяется на `/outlines` и `/generations` через общий контракт Brief.

Frontend и backend проверяются на одном наборе примеров `backend/tests/fixtures/slide_count_cases.json`. Поведение старых сохранённых презентаций, ограничения входа, клавиатурная отправка и ручное изменение количества учитываются в проверках.

Причина исправления: запрос «из пяти слайдов» отправлялся вместе с сохранённым значением 10; модель возвращала пять, валидация требовала десять и тратила дополнительные вызовы. Проверка исходного задания показала успешное завершение с тремя вариантами по пять слайдов и предупреждением о недоборе относительно десяти.
