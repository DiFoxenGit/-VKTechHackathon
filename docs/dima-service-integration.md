# Интеграция D1–D6 с сервисом Степана

17 октября 2026. В локальную ветку `codex/final-analytics-integration` перенесён коммит Димы `bb1e712` из `origin/feat/dima-data-analytics` с сохранением авторства. GitHub main проверен: `003eef6`. Основные ветки и SourceCraft не изменялись.

## Граница модулей

`designer.analytics` — исходный модуль Димы без изменений. Он импортирует, профилирует, вычисляет и выбирает визуализацию. Временный вычислительный модуль Степана удалён.

`designer.analytics_bridge` — адаптер сервиса: хранение полного Dataset, сохранение исходного AnalysisRequest, перевод готового результата в нативный Visual, разбиение на страницы и проверка перед отображением/экспортом. Новых аналитических расчётов в адаптере нет.

В записи материала `datasets[].contract` хранится полный Dataset 1.0. Оригинальные байты сохраняются в `source.bin`. В записи презентации `analysis_results` содержит неизменённые AnalysisResult 1.0; `sources[].resolved_analysis_requests` содержит отдельные доверенные запросы для повторной проверки. Поле `analysis` оставлено как представление для существующего редактора: каждый элемент содержит исходный результат в `contract` и готовые объекты слайдов. Это внутренний адаптер, не замена контракта Димы.

Перед вёрсткой, аудитом, правкой и экспортом результат перепроверяется через `verify_result` по сохранённым Dataset и AnalysisRequest. Дополнительно сверяются все категории, значения, источник и проверенный заголовок в Visual. Изменённые факты, доказательства или пары категория/значение отклоняются. Исходные строки, фильтры и доказательства не отправляются в текстовый контекст модели.

## API и интерфейс

- `GET /api/v1/content-packs/{id}/analysis?goal=...` — автоматический анализ.
- `POST /api/v1/content-packs/{id}/analysis` — тело `{"goal":"Распределение", "requests":{"DATASET_ID":{"task":"distribution","metrics":["c2"],"unit":"RUB"}}}`.
- Оба метода возвращают `analysis_results` по контракту Димы, `items` для редактора и отчёт импорта `file_report`.
- `POST /api/v1/generations` принимает `analysis_requests: {DATASET_ID: AnalysisRequest}` и прежние `analysis_goals: {CONTENT_PACK_ID: "цель"}`. Результат preview не используется как доверенный источник; при генерации модуль вызывается заново.

После «Проверить данные» интерфейс позволяет уточнить задачу, измерение, метрики, разделение на серии, агрегацию и известную единицу. Параметры сохраняются в черновике и передаются в генерацию. Для неоднозначного распределения сначала виден отказ; после выбора одной метрики — результат и ранжированные кандидаты. В общем случае варианты выбираются модулем, недопустимые варианты не добавляются ради количества.

Таблицы и большие списки категорий разбиваются без потери данных; широкие таблицы получают дополнительные страницы с повторением первого столбца. Поддерживается фильтрация из AnalysisRequest. Серии разбиваются по `series_pages` из модуля (по 5 на страницу), категории — по `pages`; поддерживается произведение страниц. Физические ограничения редактора: 2000 точек scatter, максимум 30 слайдов. Превышение возвращает объяснение, данные не обрезаются. Пропуск формулы XLSX без кеша теперь сохраняется как null с предупреждением согласно контракту Димы.

Презентации, сохранённые прежней временной аналитикой, для новых проверок нужно пересоздать из сохранённых материалов. Старые готовые файлы PPTX/PDF остаются самостоятельными артефактами.

## Проверка

```powershell
$env:PYTHONPATH=(Resolve-Path backend).Path
.venv\Scripts\python.exe -m pytest backend/tests -q
.venv\Scripts\python.exe tools/check_analytics_integration.py --url http://127.0.0.1:8004/api/v1
```

Текущий локальный backend: `http://127.0.0.1:8004/api/v1`, интерфейс: `http://127.0.0.1:5173/`. Порт запуска берётся из игнорируемого `.env`; клиентский адрес — из `.env.local`. Секреты в браузер не передаются.

- **342 passed, 12 skipped**. Включены исходные и новые тесты Димы, а также 8 проверок границы интеграции. Три опубликованных JSON-примера совпали с ответами модуля полностью.
- Все 7 HTTP-preview совпали с JSON-эталонами Димы полностью. 240 строк каталога сохранились; суммарно получено 30 слайдов и 3 варианта. Нативные категории/значения прочитаны обратно из PPTX; PDF содержит 30 страниц. Время с экспортами: 31,802 с.
- Другой корпоративный шаблон: исходный AnalysisResult тот же, 3 варианта, 2,511 с.
- Изменение CSV: пересчитаны данные и заголовок, получены PPTX/PDF, подмена значений через PATCH отклонена с 422; 18,478 с.
- Ошибок аудита нет. Для семи англоязычных наборов сохранены 54 предупреждения: 30 о языке источника, 23 о повторении оговорки на страницах каталога, 1 о повторной демонстрации одного результата из другого файла. Эти предупреждения не скрыты.
- Браузер: отказ → выбор `amount` → единица RUB → гистограмма; медиана 533,5; нативный PPTX после изменения оформления содержит все 60 наблюдений. Ошибок консоли нет.
- Frontend check и production build прошли. Реальная VK-генерация свободного текста проверена в предыдущем прогоне; этот прогон проверяет детерминированную аналитику и не вызывает модель для пересчёта чисел.

Свежие файлы: `output/dima-integration/`. Браузерные сценарии — `frontend/scripts/qa-dima-integration.cjs`; локальные скриншоты и выгрузка — в соседнем frontend checkout, `output/playwright/`.

## Обновление перед публикацией

Подтянут и включён новый коммит Димы `108199a`: нормализация процентов/времени XLSX, явный `number_locale`, сопоставимость периодов и составов, точность чисел и страницы серий. Адаптер учитывает `series_pages` без потери пар категория/метрика. Пустой лист XLSX отмечается как отклонённый, заполненные листы сохраняются. В UI добавлен выбор десятичного разделителя. Вычисление аналитики внутри async-пайплайна перенесено в threadpool.

Для frontend объединён актуальный `origin/master` с интеграционной веткой; конфликты повторно внесённых изменений разрешены с сохранением функциональности. Новые проверки: 25 категорий × 12 метрик дают 6 слайдов без потерь; XLSX с пустым и заполненным листом сохраняет таблицу и отчёт отклонения.
