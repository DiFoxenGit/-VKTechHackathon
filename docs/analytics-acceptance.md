# Проверка готовности D1–D6 · 17 октября 2026

Область: модуль `backend/designer/analytics`, его контракт, примеры и тесты.
Это не приёмка всего сервиса. Пайплайн, HTTP, UI, старые валидаторы, рендерер и экспорт не изменялись.
Требования команды сверены с `final-tasks.md`; задачи Стёпы и Андрея не выполнялись.

## Реальные доступные материалы

Машинный отчёт: [`samples/analytics/acceptance-inputs.json`](../samples/analytics/acceptance-inputs.json).
В нём — SHA-256, размеры, число таблиц/строк, причины отказов, сохранность контекста и перепроверка.
Содержимое исходных файлов в отчёт не копируется.

|---|---|
| `samples/source/материал-инициатива.md` | Таблиц нет: `import.no_table`; цифры из прозы не превращаются в выдуманный датасет |
| `samples/source/материал-продукт.md` | То же: корректный отказ вместо ошибочного `ragged_rows` |

| `docs/test-run.md` | 4 таблицы: 6, 5, 6, 6 строк; перепроверка справочного представления проходит |
| Внешний `final-tasks.md` | 7 таблиц: 3, 12, 10, 7, 6, 5, 23 строки; данные обработаны как данные, не как команды |
| `samples/content-pack/visual-pack.zip` | Ассеты и их манифест не являются табличными данными; каждый отказ отражён в отчёте |
| «Переделка чужой презентации 27.09.zip» | Неподдерживаемые вложения и текст без таблиц возвращаются в rejected, ничего не скрыто |
| «Презентации сервиса 27.09.zip» | Проверен только размер: превышает 20 MiB; импорт не заявляется как выполненный |

Рабочих CSV/XLSX вне сгенерированных примеров в доступной папке команды не найдено.
Поэтому реальные бизнес-итоги и совместимость с рабочими книгами команды **не подтверждены**.
XLSX проверен на воспроизводимых OOXML-файлах с несколькими листами, датами, кешированными/некешированными
формулами, заголовком отчёта, пустыми листами и стилями процентов. Это граничные тесты, а не реальные книги.

## D1. Импорт

| Критерий | Проверка и статус |
|---|---|
| CSV, разделители, кавычки, BOM, десятичная запятая/пробелы | Проверено; дополнительно поддержан `sep=;` Excel и координаты начала многострочной записи |
| XLSX: несколько листов, заголовки, пустые строки | Проверено на граничных файлах; пустые/только-заголовочные листы перечисляются в rejected, остальные сохраняются |
| Формулы без сохранённого значения | Null с адресом ячейки; даже строка только с формулой не исчезает; формулы не исполняются |
| Табличный JSON | Объектные строки и columns/rows; пропущенные ключи — null/предупреждение; дубликаты ключей, вложенные значения и неоднозначные структуры — отказ |
| Таблицы TXT/MD и контекст | Проверено на документах команды; распознаются заголовок/разделитель Markdown, кодовые блоки не подменяют таблицы |
| ID и координаты | Хеш байтов + путь ZIP + лист/номер; ID колонок и исходные номера строк сохраняются |
| Полный источник отдельно от слайда | Dataset не обрезается; большие целые передаются точными десятичными строками |
| Передача/хранение в контент-пакете/ZIP | Контракт, импорт и явные rejected готовы. Постоянное хранение и подключение загрузчика — зависимость от Стёпы; подтверждения согласования нет |

Критерий равенства CSV/XLSX/JSON проверен на одной таблице в трёх форматах: значения, типы,
число различных значений и выбранная аналитика совпадают. Неоднозначные `1,234` требуют number_locale;
догадка о тысячах не выдаётся за проверенное число.

## D2. Профиль

| Критерий | Проверка и статус |
|---|---|
| Числа, даты, категории, текст; числовые ID | Проверено; коды с ведущими нулями и поля ID/ИНН/телефона не становятся метриками |
| Время, измерения/метрики, уникальные значения | Проверено; distinct чисел считается по значениям, не по строковому оформлению 1/1.0/1.00 |
| Пропуски, подозрительные значения, выбросы | Проверено; 1,5 IQR/inclusive; выброс сохраняется. NA в категориальном поле не теряется как пропуск |
| Иерархии с проверкой | Проверяется наблюдаемая many-to-one зависимость; это кандидат, не утверждение о бизнес-семантике; лимит перебора явно предупреждается |
| Размер, периодичность, неоднозначность | Проверено: дата 01.01→28.02 не считается регулярной месячной осью; неоднозначные slash-даты/числа не дают уверенного расчёта |
| Не удалять/не заполнять без политики | Проверено: исходные строки остаются; отсутствующие месяцы/годы представлены null в визуализации |

Проценты Excel декодируются из долей в процентные пункты с `Column.unit=%` и
`Column.normalization=excel_percentage_points`; смешанный формат одной колонки отклоняется явно.
Исходный файл обязан сохраняться интеграцией; метаданные объясняют преобразование представления ячейки.
Почасовые ISO-метки не усекаются до дня; часовые пояса нормализуются к UTC. Смесь aware/naive
возвращает отказ. Время Excel без даты остаётся числом в сутках с явной нормализацией, без фиктивной даты.

## D3. Задача и визуализация

| Критерий | Проверка и статус |
|---|---|
| Динамика, сравнение, доли, распределение, связь, справка | Проверено для всех шести задач; дополнительно KPI/summary |
| Цель из брифа/контента | Проверено: явный бриф приоритетен; Goal/Цель и отдельные «Сравнить регионы» вне таблиц учитываются; строки ячеек не становятся целью |
| 2–3 ранжированных варианта с объяснениями | Проверено; причина включает задачу, число строк/метрик, измерение, число категорий и периодичность |
| Допустимость отдельно от предпочтений | Проверено: pie без целого/с отрицательными частями запрещён; scatter требует пары метрик; stacked — складываемых рядов |
| Независимость от формата | Проверено на CSV/JSON/XLSX |
| Независимость от шаблона | Входа шаблона в модуле нет; одинаковые Dataset/Request дают одинаковое решение. Сохранность решения при двух реальных экспортах — зависимость от Стёпы |
| Недостаток данных | Отказ с кодом причины; единственная таблица не дополняется фиктивными альтернативами |

Контрольный набор «месяц × регион × продажи» даёт line для динамики и bar для итогов регионов.
Правила детерминированные и консервативные; произвольное понимание любой естественной формулировки не заявляется.

## D4. Вычисления

| Критерий | Проверка и статус |
|---|---|
| Суммы, количество, среднее, медиана, рост, доли, KPI | Сверены с независимыми ответами; Decimal-расчёты; count имеет единицу observations |
| База, единицы, периоды | Нулевая/отрицательная база не даёт роста; RUB/USD или неизвестная валюта не суммируются; 1 week/6 weeks не сравниваются напрямую |
| Сопоставимость состава групп | Изменение набора регионов/пропуск крайних значений исключает уверенный процент роста |
| Проценты и процентные пункты | Проверено: 10%→15% — 5 п.п.; произвольное усреднение/сумма готовых процентов не разрешены |
| Гистограмма и X/Y | Проверены границы интервалов (последняя включена), частоты, медиана и пары одной строки |
| Пропуски | Нет нулевой подстановки; null сохраняется и для отсутствующего периода, и для отсутствующего ряда |
| Большие таблицы/категории/серии | Все 240 строк и итог 28 920 проверены; pages/series_pages содержат всё ровно один раз, без top-k и скрытого «прочее» |
| Лимит 30 слайдов | Проверяется произведение страниц категорий и рядов; slide_budget позволяет зарезервировать место под другие слайды |
| Причинность | Не выводится из scatter; предупреждение обязательно |

Значения за пределами безопасного диапазона чисел графика дают `analysis.numeric_precision`,
а не два одинаковых числа из разных больших целых. Исходник и справочное представление сохраняют точность.
Очень большая кардинальность отсекается по бюджету до построения фактов; группировка рядов выполняется
через индекс, без повторного сканирования всех строк для каждого ряда.
Дополнительно проверен полный источник на 100 000 строк: сумма 5 000 050 000 и доказательство
по всем 100 000 исходным строкам. Это отдельный синтетический масштабный тест, не бизнес-данные.

## D5. Доказательства

| Критерий | Проверка и статус |
|---|---|
| Операция, координаты, единицы, период, точность | Fact.exact + конечное значение графика + Evidence; доли ссылаются на факты числителя и знаменателя |
| Заголовки по проверенным фактам без модели | Проверено: рост, доля, лидер, последнее наблюдение; пустой первый ряд не ломает вывод по доступному ряду |
| Новое правило для производных чисел | verify_result готов и обнаруживает подмены. Замена старого запрета в генерации/аудите — совместный незакрытый пункт, зависит от Стёпы |
| Не общий whitelist | Пересчёт Dataset+Request, проверяется весь результат и привязка категории к значению |
| Перестановка категории/значения | Проверено отрицательными тестами; исходные 1/2/3 не ошибочно считаются нумерацией |
| Запрет модели менять готовые данные | В модуле нет модели. Проверка после модельного/редакторского этапа предоставлена; обязательный вызов в сервисе — зависимость от Стёпы |

Рост проходит модуль и verify_result. Прохождение через существующие генерацию и аудит пока не доказано:
без подключения и изменения старого правила этот общий критерий D5 закрыть нельзя.

## Как повторить

Из корня репозитория с зависимостями backend:

```sh
python tools/make_analytics_samples.py
python tools/check_analytics_inputs.py --output tmp/analytics-input-audit.json
cd backend
python -m pytest -q tests/test_analytics.py tests/test_analytics_acceptance.py tests/test_analytics_import_edges.py
```

Полный pytest и CI также включают эти проверки. LibreOffice нужен для существующих экспортных тестов.
Проверка технических Markdown-таблиц не доказывает правильность бизнес-аналитики реальных CSV/XLSX.

Локальный итог после исправлений: **327 passed, 3 skipped**; все **95 проверок аналитики** проходят.
Пропущены существующие экспортные проверки без LibreOffice. Выполнены diff --check и ручная проверка
качества/безопасности; упрощённый security-скан не нашёл опасных паттернов. Gitleaks/semgrep/osv-scanner
локально отсутствуют, поэтому полный автоматический security-аудит не заявляется. Общий check.sh
не распознаёт Python-проект; вместо него выполнен полный pytest. Результат CI — в PR #62.

## Что остаётся у Стёпы

1. Сохранить исходные байты и полный Dataset в контент-пакетах, показывать accepted/rejected по файлам/листам.
2. Подключить AnalysisResult перед планированием, не давать LLM заново формировать числа.
3. Передавать подходящий slide_budget, учитывать pages × series_pages и null-разрывы.
4. Заменить старый запрет производных чисел на проверку доказательств; вызывать verify_result на доверенных входах.
5. Сохранить данные/ссылки/доказательства через редактирование и все варианты вёрстки.
6. Показать альтернативы/объяснения/предупреждения; проверить два шаблона и реальные PPTX/PDF.

Новые опциональные поля draft-контракта: Column.unit/normalization, ColumnProfile.missing_periods,
AnalysisRequest.number_locale и VisualData.series_pages. Схемы и три комплекта примеров обновлены.
Это изменения внутри незавершённого PR, а не доказательство уже состоявшегося согласования интерфейса.
