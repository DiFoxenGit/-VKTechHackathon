# Заголовки из проверенных фактов и путь главного экрана

## Изменение Димы

`business-editorial-4` передаёт текстовой модели два рассчитанных допустимых заголовка на каждую каноническую страницу. Модель выбирает формулировку; сервер проверяет точное соответствие меню и раскрывает факт-токены. Вопросы и произвольная оценка выполнения плана отклоняются.

Направления роста/снижения, нулевое изменение, отсутствие базы, выполнение/недовыполнение/превышение плана определяются по точным расчётным значениям. Для изменений, округляемых до нуля, и выполнения плана, округляемого до целевого уровня, используются нейтральные формулировки. У решений и рисков сохраняются оговорки об отсутствии доказанной причины и рассчитанного эффекта инвестиций.

Числа, единицы, периоды, источники, графики, таблицы и условия не редактируются моделью. Сохранённые `business-editorial-2/3` воспроизводятся по историческим правилам; новые требования не переписывают старые документы.

Примеры: [`baseline-and-b.json`](../samples/business-acceptance/conclusion-review-v4/baseline-and-b.json). Это синтетические рассчитанные примеры без вызова модели, а не доказательство живого инференса. Исходники — прежние `data-v1` и `period-context-v1`, контракт `AnalysisResult` и business-sidecar не изменён.

## Проверка кода главного экрана

Оба стенда собираются из одного исходного кода; различаются базовые URL (`/` и `/presentations/`).

1. `App.startDeck` вызывает `presentationService.generate` либо `generateBatch`.
2. Одиночный запуск отправляет реальный `POST /generations`, пакетный — `POST /generation-batches`. Оба обработчика передают работу в одну серверную очередь и `run_generation`. Ошибка сервера не заменяется демонстрационной презентацией.
3. При `llm_configured=true` из ответа `/templates` одиночный запуск не передаёт готовый `outline`: для обычного текстового задания сервер запрашивает структуру у модели. Если флаг ложный, одиночный путь передаёт предварительную структуру фронтенда. Пакетный путь её не передаёт.
4. Для бизнес-датасета сервер сначала рассчитывает защищённые факты и каноническую историю, затем запрашивает модельную редактуру. Отсутствующий `model_content_generation` не выключает её: только явный `false`. Для обычных аналитических наборов расчётный путь может обходиться без текстовой модели.
5. Превью и новые документы приходят с сервера. При переключении оформления редактор сохраняет новую серверную ревизию. Перед скачиванием изменённая серверная презентация сохраняется, затем экспорт скачивается с сервера. Локальный экспорт остаётся для локального документа без серверной ревизии.

Поэтому одинаковый реальный пайплайн не гарантирует одинаковый результат при разных вводных: мои приёмочные задания загружают полный бизнес-набор, явно задают периоды/условия и 12 слайдов; пользовательский текстовый запрос без файлов, с другим количеством слайдов и автоматическим выбором изображений выбирает другую ветвь. Модель также не обязана дословно повторять прошлый ответ.

Проверка ограничена кодом, тестом сервиса фронтенда и доступностью конфигурационного флага на обоих сайтах. Сравнение конкретных пользовательских презентаций и новый платный запуск из интерфейса не выполняются. Вёрстка, интерфейс и задачи Стёпы/Андрея не изменены.

## Проверки

Регрессии покрывают базу/B, оба допустимых заголовка каждой страницы, сохранность аналитики, знаки/округление/неопределённость, ложное заявление о выполнении плана, вопросы и воспроизведение v2/v3. Живые проверки после доставки фиксируются отдельно по реальным ответам провайдера; fallback не считается успешной проверкой ВК.
