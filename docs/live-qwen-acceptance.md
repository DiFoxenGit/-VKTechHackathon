# Приёмка S8–S9: команды и доказательства

Обновлено 19.10.2026. Эти команды описывают процедуру; наличие скриптов и зелёных
управляемых тестов не означает успешную приёмку живой Qwen. Запускать полную живую
матрицу после успешной одиночной проверки транспорта и сервиса. При HTTP 500,
ошибке авторизации, лимите или таймауте сначала устранить причину на стороне
окружения/провайдера; не нагружать сервис повторением всей матрицы.

Клиент: существующий `designer.ai.ask` через `complete_json`. Профиль:
`DESIGNER_LLM_PROVIDER=vk`, модель `qwen38-27b-fp8`. Ключ находится только в
закрытом окружении или ignored `.env.local`. Скрипт не печатает заголовки,
исходные запросы, ответы провайдера и значения ключей.

В примерах `python` — Python с backend-зависимостями проекта. На текущем стенде
это `C:/Users/Степан/OneDrive/Документы/ChatGPT/VKTechHackathon/.venv/Scripts/python.exe`;
окружение используется без изменений. Для экспорта API должен видеть LibreOffice
через `DESIGNER_SOFFICE`. Дополнительные пакеты для основных проверок не нужны:
используются существующие `httpx`, `python-pptx`, `pypdf`, backend и `pytest`.

## Одиночная проверка

```powershell
python tools/check_inference.py --env-file .env.local --attempts 1 --output output/final-qwen/inference.json
```

Проверка обязана получить реальный HTTP-ответ, разобрать JSON и проверить точную
схему `{"ok": true}`. В отчёте сохраняются дата UTC, commit, branch, признак
незакоммиченных изменений, профиль, модель, режим JSON, попытки, коды HTTP,
длительность, validation, response ID/хеш и usage при наличии. Название модели
и `llm_configured` не считаются доказательством запроса.

Для проверки полного бизнес-пути на одном загруженном шаблоне:

```powershell
python tools/check_inference.py --env-file .env.local --service http://127.0.0.1:8036 --template-id TEMPLATE_ID --output output/final-qwen/inference-service.json
```

Этот запуск делает один диагностический транспортный вызов и отдельное
содержательное задание с тремя оформлениями. Он не заменяет независимые повторы
полного набора. Транспортный вызов не входит в замер генерации бизнес-колод.

## Полная живая приёмка

```powershell
python tools/check_live_acceptance.py --url http://127.0.0.1:8036/api/v1 --output output/final-qwen/live-acceptance
```

API должен содержать ровно три оригинальных корпоративных шаблона. При наличии
других шаблонов передать три повторяющихся `--template-id TEMPLATE_ID`.
Сценарии выполняются последовательно; внутри базового сценария три задания
запускаются параллельно под одним таймером:

1. Baseline Q2: три шаблона × classic/focus/split, 9 колод, 3 независимых задания.
2. Версия B Q2: один шаблон × 3 оформления, обновлённые продажи и условия.
3. Другой допустимый период Q3: отдельные settings, цитата периода и контекст
   горизонта действий; один шаблон × 3 оформления.
4. Два новых повтора полного baseline-запроса на одном шаблоне, каждый с новым
   заданием и содержательным вызовом; 6 колод.
5. Семь видов данных в каждой из 9 колод: три шаблона × три оформления.
   Здесь `model_content_generation=false` намеренно: это отдельная проверка
   расчётов и экспорта, она не засчитывается в живые ответы Qwen.

Итого: 7 независимых бизнес-заданий, 21 бизнес-колода и 9 колод семи видов
данных. Число HTTP-попыток может быть больше 7 при разрешённых сервером повторах.
Девять базовых колод не объявляются девятью ответами модели: snapshot inference
общий внутри трёх вариантов одного задания, `content_reused_for_variants=3`.
Отчёт отдельно считает валидированные вызовы, попытки, distinct response IDs,
distinct хеши содержимого и fallback. Одинаковый текстовый хеш двух ответов
сам по себе не доказывает кэш: модель может ответить одинаково. Если провайдер
не возвращает response ID, в отчёте явно указывается недоступность/неполнота
этой метрики. Независимые вызовы в этом случае подтверждаются отдельными job IDs,
журналами фактических HTTP-ответов с успешной проверкой и хешами ответов/исходников.
ID провайдера и usage сохраняются при наличии; отсутствие этих необязательных
полей само по себе не отклоняет живую модель. Уникальность response IDs проверяется,
когда они доступны для всех проверенных ответов. Уникальность текста не требуется.

Для отдельного базового замера:

```powershell
python tools/check_parallel_generation.py --url http://127.0.0.1:8036/api/v1 --scenario business --live --label parallel-live --output output/final-qwen/parallel-live
```

Ключ `--images` включает изображения в запрос. Использовать его для повторного
полного замера после передачи Димой работающего image-контракта. Отчёт сохраняет
фактический `image_generation` каждой колоды. Если изображения не включены,
результат не объявляется замером полного сценария с изображениями.

## Проверки без запросов к модели

```powershell
python tools/check_parallel_generation.py --url http://127.0.0.1:8036/api/v1 --scenario business --label deterministic-business --output output/final-qwen/deterministic-business
python tools/check_parallel_generation.py --url http://127.0.0.1:8036/api/v1 --scenario seven-types --label deterministic-seven-types --output output/final-qwen/deterministic-seven-types
python -m pytest backend/tests/test_acceptance_tools.py -q
```

Без `--live` скрипт передаёт `model_content_generation=false` и требует
`requested=false`, `attempted=false`, `completed=false`, пустой журнал вызовов.
Он не может незаметно пройти через модель или выдать расчётную колоду за Qwen.
В управляемых тестах проверяются ложноположительные состояния, невалидный ответ,
fallback, 429 с успешным повтором, отсутствие HTTP-доказательства, неизвестная
идентичность ответа, подмена независимых фактов и исходных строк, а также
сравнение чисел нативных объектов Office вместо простого подсчёта объектов.
Отказы реального провайдера искусственно не воспроизводятся.

## Что входит в отчёт

`report.json` сохраняется после каждого задания/экспорта, включая ошибочный
запуск. Живой режим завершается ошибкой при fallback, отсутствии валидации или
фактического HTTP-вызова. Флаг `model_content_generation` вычисляется из успешно
проверенной серверной телеметрии. По каждой колоде проверяются:

- Все 15 числовых ответов независимого `tools/business_reference.py` с Decimal,
  выбранные периоды и ссылки на строки продаж/плана в `business_proof`.
- Ссылки на факты и контекст каждой страницы; для live — происхождение
  `validated_model` и до/после минимум трёх изменённых заголовков.
- Отсутствие ошибок штатного аудита; сохранение ревизии и повторное открытие.
- Все семь dataset IDs в каждой колоде семи видов данных.
- Число страниц PPTX/PDF; редактируемые графики и таблицы; точные значения
  нативных рядов и нормализованные числовые ячейки таблиц.
- Наличие сохранённых заголовков, KPI и ячеек таблиц в фактическом PDF;
  SHA-256 каждого экспортированного файла, отдельное время PPTX/PDF экспорта.

Общий таймер начинается перед отправкой трёх `/generations` и заканчивается
после готовности всех девяти результатов. Очередь, запросы Qwen, ограниченные
повторы и сборка PPTX входят в него. Загрузка и предварительный расчёт анализа
вынесены заранее и явно отмечены. Экспорт PDF выполняется после таймера и имеет
собственные длительности. Превышение пяти минут сохраняется как фактическое
время и `within_five_minutes=false`, без подмены результатов старым замером.

## Визуальная проверка и границы автоматизации

Автоматические проверки не подтверждают смысловую полноту рекомендаций,
отсутствие всех визуальных наложений и качество композиции. Перед передачей
Андрею просмотреть фактические PDF всех девяти базовых колод и приложить четыре
крупных образца: обложка WorkSpace, региональные отклонения/страница 5 split,
риски VK Tech split/страница 11 и действия/страница 12. Проверить заполнение
карточек, отрицательные значения, подписи и редактирование нативных объектов.
Отдельно пройти браузерный путь в 1440×900 и 1920×1080, сделать содержательную
правку, сохранить и открыть повторно. В отчёте автоматизации статус этого этапа
остаётся `visual_review=pending`, пока материалы не проверены человеком/агентом.

Результат API на сломанном провайдере может доказать честную обработку ошибки и
работоспособность fallback. Это полезный отдельный материал, но не успешная
живая приёмка S8–S9. HTTP 500 не является основанием незаметно сменить модель,
профиль или выключить JSON-режим без установленной причины.
