# Визуальные ассеты: иконки, иллюстрации, фактоиды

Слайды выходили голым текстом: заголовок и три пункта мелким кеглем, иконки — примитивы из автофигур (звезда, шестерёнка), картинок нет. При этом в шаблонах кейса лежат сотни готовых элементов: у VK Education — каталог из 208 интерфейсных иконок, у VK Tech — 3D-иллюстрации и иконки сервисов, у WorkSpace — круглые пиктограммы. Сервис их не использовал.

Этот документ описывает, откуда теперь берутся картинки, как они подбираются к тексту и как попадают на слайд.

## Три источника картинок

| Источник | Что это | Приоритет |
|---|---|---|
| Контент-пакет | zip с SVG, PNG, JPEG (и текстами), одиночная картинка или PPTX, из которого забираются картинки | высший: пакет собран под эту презентацию |
| Шаблон | картинки со страниц-образцов, собранные при импорте | средний: стиль бренда |
| Встроенный набор | 63 иконки и 13 иллюстраций в SVG, `backend/designer/assets/pack/` | запасной: есть всегда |

Библиотека колоды собирается функцией `assets.library(template, packs)` из всех трёх источников. При равном совпадении побеждает более приоритетный источник.

## Встроенный набор

Нарисован с нуля генератором `tools/make_content_pack.py`, без чужих наборов:

- **иконки** — сетка 24×24, обводка 2 px, скруглённые концы, цвет `currentColor`;
- **иллюстрации** — 400×300, плоские, цвета записаны **ролями**: `var(--accent)`, `var(--accent2)`, `var(--soft)`, `var(--muted)`, `var(--paper)`, `var(--ink)`.

Роли при вставке превращаются в цвета слайда (`assets.color_roles`): акцент и второй акцент — из палитры шаблона, `paper` — фон, `ink` — цвет текста, `soft` и `muted` — их смеси. Поэтому одна иллюстрация выглядит своей и на белом VK Education, и на чёрном WorkSpace.

У каждого ассета есть теги — корни слов (`команд`, `запуск`, `бюджет`, `рост`…). Генератор пишет `manifest.json` и заодно собирает тот же набор загружаемым пакетом `samples/content-pack/visual-pack.zip`.

```bash
python tools/make_content_pack.py
```

## Картинки шаблона

`assets.harvest_pptx` при импорте обходит слайды шаблона (вместе с группами) и раскладывает картинки по видам по их пикселям (`inspect_image` + `classify_image`):

| Вид | Признаки |
|---|---|
| иконка | прозрачный фон, один цвет, почти квадрат, маленькая рамка на слайде |
| иллюстрация | прозрачный фон, много цветов, сторона от 96 px |
| фото | непрозрачное, пёстрое, сторона от 200 px |
| не берётся | повторяющийся брендинг, картинки во весь слайд (фон), градиентные полосы, значки приложений и логотипы (квадрат почти без прозрачности) |

Одноцветность считается только по плотным пикселям: у сглаженного белого глифа края серые, и без этого белые иконки не узнавались. Картинки пишутся в `templates/<id>/assets/<sha>.<ext>`, метаданные — в запись шаблона (`template.assets`). Лимиты: 320 иконок, 60 иллюстраций, 40 фото.

### Подпись моделью

Иконку без подписи подобрать к тезису нельзя. Её подписывает агент `assets` (`prompts/assets.v1.txt`): мультимодальная модель видит контакт-лист из 16 пронумерованных картинок и возвращает по 2–4 русских слова на каждую. Подписи превращаются в корни (`assets.stem`) и хранятся в записи шаблона, при переразборе шаблона они сохраняются по идентификатору картинки.

Подпись запускается:

- автоматически на этапе `assets` задачи генерации, если задан `DESIGNER_VLM_MODEL` (не дольше 120 секунд, неподписанное остаётся на следующий раз);
- вручную: `POST /api/v1/templates/{id}/assets/tags`.

Без мультимодальной модели картинки шаблона просто не участвуют в подборе, и работает встроенный набор.

## Контент-пакет с картинками

`POST /api/v1/content-packs` принимает:

- zip — тексты идут в материалы, картинки в ассеты;
- одиночную картинку SVG, PNG или JPEG;
- PPTX — берётся текст, а картинки собираются так же, как у шаблона.

`manifest.json` в корне zip необязателен:

```json
{"assets": [{"file": "icons/rocket.svg", "kind": "icon", "tags": ["запуск", "ракета"]}]}
```

Без манифеста вид берётся из папки (`icons/`, `illustrations/`, `photos/`, а также русские названия) или по самой картинке, а теги — из имени файла (`запуск-ракета.svg`). Нечитаемые файлы пропускаются, пакет без текста и без картинок отклоняется с 422.

SVG разбирается безопасно (`assets.parse_svg`): lxml без внешних сущностей и сети, `script`, `defs` и прочее не исполняются, размер ограничен 400 КБ. Поддерживаются `path` (все команды, включая дуги со слитыми флагами), `circle`, `ellipse`, `rect`, `line`, `polyline`, `polygon`, группы, `transform` и цвета: hex, `rgb()`, `currentColor`, `var(--роль)`.

## Подбор по смыслу

`assets.match_score` сравнивает теги с началами слов текста: корень `команд` совпадает с «команды» и «командам». Короткий корень (до трёх букв) совпадает только с короткими словами, иначе «цел» нашёл бы «целиком». Раньше стоящие слова весят больше — смысл тезиса обычно в первом существительном («**Время** сборки колоды сократилось» — про время, а не про колоду). Длинный корень весит больше короткого: «дизайнеры» — про людей, а не про «дизайн».

- **Иконки** (`pick_icons`) подбираются к ряду подписей **из одного набора**, чтобы ряд был в одном стиле. Выигрывает набор, покрывший больше подписей; неподобранная подпись получает нейтральный знак того же набора. Набор без нейтрального знака берётся, только если в нём нашлось всё. Одна иконка на слайде не повторяется.
- **Иллюстрации и фото** (`pick_picture`) — по заголовку (вес 1,5) и тезисам; уже использованная в колоде картинка штрафуется.

## Композиции слайда

`layout.slide_mode` решает, как подать слайд с тезисами без визуализации. Обложка и финальный слайд не трогаются: там композицию задаёт страница шаблона.

| Режим | Когда | Как выглядит |
|---|---|---|
| `stats` — фактоиды | в 2–4 тезисах есть весомое число и не больше одного тезиса без него | крупная цифра акцентным цветом, под ней тезис, слева акцентная черта. classic — ряд плиток, split — сетка в две колонки, focus — одна цифра героем и остальные тезисы текстом |
| `icons` — список с иконками | classic, 2–5 тезисов, иконки нашлись хотя бы для половины | иконка слева от каждого тезиса, тезисы на одной вертикали |
| `picture` — текст и картинка | split (до 4 тезисов), focus (до 2), classic (1); нашлась иллюстрация или фото | текст слева, картинка справа, текст по её вертикальному центру |

**Число фактоида берётся из тезиса дословно** (`layout.stat_value`): «с 186 до 4 минут» → «4 мин», «4 минуты вместо 186» → «4 мин», «2 из 68», «23%», «1 400 ₽». Выдумать число фактоид не может, а аудит сверяет числа с источниками, как и раньше.

Кегли — ступени шкалы шаблона: цифра — самая крупная, которая помещается в плитку, тезис — кегль тела шаблона. Для своих композиций кегль тела не опускается ниже общего по шаблону: мелкий кегль подписи образца здесь не наследуется.

### Иконки в гнёздах шаблона

Карточные страницы шаблонов (например, «Тезис под тематической иконкой» у VK Education) держат над каждой карточкой значок-образец. Сам значок — пример («лампочка»), а место и цвет — решение дизайнера.

При разборе такие значки запоминаются как `pattern.icon_slots`: одноцветный глиф (не плашка под ним) в рабочей области, с рамкой в координатах слайда (с учётом группировки) и цветом. При вёрстке (`layout.swap_icons`) над каждой карточкой ставится иконка по смыслу её тезиса — в ту же рамку и в тот же цвет, а образец снимается, в том числе изнутри группы. Плашка под значком остаётся.

Если в classic нашёлся список с иконками, а выбранная страница — карточная с местами под значки и тезисы помещаются в карточки, берётся страница шаблона: это тот же список с иконками, только нарисованный дизайнером.

### Чистая сцена

На слайдах со своей композицией и с диаграммой мелкие образцы страницы — стрелки, соединители, точки, значки — не переносятся (`parsing.stage_clutter`): площадь меньше 5% слайда, центр в рабочей области, не повторяющийся брендинг и не рисунок макета (его убрать нельзя, он приходит с макетом). Вёрстка их не обходит, экспорт не копирует, аудит не проверяет на наезд. Раньше такие стрелки из страницы «Оформление схем» оставались поверх текста.

Там же диаграммы получили всю рабочую область вместо рамки текста образца и стали заметно крупнее.

## Экспорт

- SVG → нативные фигуры PowerPoint (`assets.draw_vector`): окружности и прямоугольники — автофигуры, пути — freeform, всё в группе с именем `icon:<id>` или `illustration:<id>`. Иконка красится одним цветом, иллюстрация — ролями. Линии — со скруглёнными концами, как в исходнике.
- Растровая иконка перекрашивается в цвет с сохранением прозрачности (`tint_png`).
- Растровая иллюстрация вписывается целиком, фото заполняет рамку с обрезкой. Растягивания нет по построению.
- Цвет иконки и цифры фактоида — акцент, если он читается на фоне (контраст от 3:1, порог WCAG для крупного кегля), иначе цвет текста. Иконка в гнезде шаблона — цвет образца.
- Ссылка на ассет в модели слайда (`builtin:…`, `template:<id>:<файл>`, `pack:<id>:<файл>`) превращается в путь только через `assets.resolve`: имя файла — хеш и тип, выйти за папку хранилища нельзя.

Слайды по-прежнему состоят из редактируемых объектов, `verify_pptx` это подтверждает.

## Аудит

- Элемент `stat` проверяется как текст: гарнитура, кегли цифры и подписи на шкале шаблона, оценка переполнения подписи, контраст подписи к фону.
- Плитки фактоидов, начиная со второй колонки, выровнены шагом сетки (`grid`), а не направляющими шаблона, и не считаются «невыровненными».
- Иконки в гнёздах шаблона помечены `from_template`: место задал дизайнер.
- Вопрос Приложения 1 «картинки и иконки относятся к теме слайда» по-прежнему задаётся мультимодальной модели в аудите по изображению.

## API

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/v1/content-packs` | текст, картинка или zip; ответ с `assets` и `asset_counts` |
| GET | `/api/v1/content-packs/{id}/assets` | картинки пакета со ссылками на файлы |
| GET | `/api/v1/templates/{id}/assets` | картинки шаблона, виды, теги, ссылки |
| POST | `/api/v1/templates/{id}/assets/tags` | подписать картинки шаблона моделью; 503 без `DESIGNER_VLM_MODEL` |
| GET | `/api/v1/assets/{template\|pack}/{owner}/{file}` | файл картинки; SVG отдаётся с `Content-Security-Policy: default-src 'none'` |

В списке шаблонов вместо картинок — `asset_counts`. Презентация запоминает `content_pack_ids`, чтобы правка слайда и исправления собирали ту же библиотеку.

## Ограничения

- Картинки шаблона подбираются только после подписи моделью. Живой прогон подписи на `qwen3.6-35b-a3b` ещё не делался — контракт проверен тестом с подменённым ответом модели.
- Цифра фактоида не крупнее верхней ступени шкалы шаблона (у VK Education — 48 pt), поэтому «герой» в варианте focus лишь немного крупнее заголовка.
- Если пакет пользователя покрывает не все тезисы слайда, ряд целиком берётся из встроенного набора — ради единого стиля.
- Генерация изображений (задача 3.1 со звёздочкой) встаёт в то же место, куда и остальные иллюстрации: нарисованные картинки добавляются в библиотеку колоды источником `generated`, с тегами из слов самого слайда, и дальше их подбирает обычный `pick_picture`. Рисуются они один раз на колоду, до вёрстки вариантов, и хранятся в `illustrations/<id>/assets`. Включается `DESIGNER_IMAGE_MODEL`; подробности — в [MODELS.md](../MODELS.md).
