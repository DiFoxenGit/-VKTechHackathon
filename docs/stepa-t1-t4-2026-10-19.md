## Общая редактура T1

`POST /api/v1/generation-batches` принимает объект `requests` из одного–трёх
обычных запросов генерации. Шаблоны должны различаться. Все поля содержания,
исходники, периоды и условия должны совпадать; различаться могут `template_id`,
`brandbook_id`, `style_overrides`. Несовпадение возвращает 422 до запуска заданий.
Ответ: `{ "id": "идентификатор пакета", "jobs": [...] }`. Дальше клиент опрашивает
обычный `GET /api/v1/jobs/{id}` для каждого задания.

Первое дошедшее до редактуры задание выполняет запрос модели. Остальные ждут его
результат, затем отдельно вызывают `validate_editorial` для своих исходников и
outline. Даже третье задание, стоявшее в очереди при `DESIGNER_MAX_JOBS=2`, получает
результат этого пакета. Координатор существует только до завершения этих заданий.
Следующий POST создаёт новый пакет и новый запрос. Обычный `/generations` сохраняет
свой независимый запрос модели и три оформления.

Владелец запроса сохраняет настоящий журнал HTTP, `content_batch_id`,
`content_source_job_id`, `content_input_sha256`. Получатели сохраняют
`shared_from_job_id`, `content_revalidated=true` и `shared_inference` с доказательством
исходного ответа. Их собственные `attempted=false`, `attempts=0`, `calls=[]`.
`content_reused_for_variants=3` относится к трём оформлениям каждого шаблона.
Отчёт проверяет связи, входной хеш, совпадение журнала и один проверенный ответ
на весь пакет. Отмена ожидающего получателя не создаёт дополнительный запрос.
Ошибка владельца освобождает ожидающие задания и включает явно отмеченный резерв.

## Короткая редактура T2

В модель передаются определения метрик, выбранные периоды, уникальные фрагменты
контекста и факты каждой страницы. Удалены повторные полные объекты фактов,
утверждения и служебные поля. JSON передаётся без лишних пробелов.

Модель возвращает `input_sha256` и 12 объектов `{id, title, hypothesis}`. Гипотеза
необязательна. Сервер добавляет защищённые интерпретации, следующие шаги и исходные
привязки, после чего выполняет прежний полный валидатор. Запрет чужих фактов,
чисел/дат/единиц вне токенов, неподтверждённых причин и неверного направления
изменения сохранён. Формат сохранённой редактуры остаётся `business-editorial-2`;
старые сохранённые ответы продолжают воспроизводиться.

Регулярные выражения для порядковых числительных используют окончания вместо
`перв\w*` и `трет\w*`. «Первоочередной», «первоначальный», «первопричина»,
«третейский» больше не вызывают ложный отказ. «Первый», «первую», «третья»,
«третьих» и остальные проверенные числительные остаются запрещены, включая
дробь «треть» и её падежные формы.

На фиксированном бизнес-наборе запрос сокращён с 42 825 до 13 484 символов
(68,51%, одинаковая компактная сериализация для сравнения). Единственный уникальный
сохранённый живой ответ прежней приёмки повторно прошёл полный валидатор без
платного вызова. Доля прохождения с первой попытки записывается в
`first_attempt_pass_rate`; транспортный отказ VK и переход в GenAPI внутри одной
редактуры не считаются дополнительным независимым ответом.

## Ожидание и повтор T4

Журнал сообщает номер попытки `model_attempt`, предел `model_max_attempts` и
безопасный код `retry_reason`. Интерфейс показывает этап «Модель редактирует текст»,
прошедшее время, попытку и объяснение повтора обычными словами. Текст невалидного
ответа в пользовательское сообщение не попадает. Получатели общего текста видят
ожидание общей редактуры.

Таймаут GenAPI имеет код `timeout` и сохраняет ID уже принятой задачи. Автоматический
повтор такого неопределённого платного запроса запрещён существующим транспортом.
После ошибки интерфейс даёт кнопку «Повторить». В редакторе повтор создаёт новую
презентацию; предыдущая ревизия и её экспорт остаются доступными.

В браузере проверены 1440×900 и 1920×1080: медленный ответ, вторая попытка,
объяснение отказа, таймер, ошибка, кнопка повтора и сохранение ревизии 2 после
неудачного повтора. Это управляемые ответы для отрицательных сценариев; они не
считаются живой приёмкой модели.

## Приёмка T1/T3

Код T1/T2/T4 реализован. Критерий T1 «три успешных S8.1 подряд менее 300 секунд»
и живая часть T3 **не приняты**. Машинные доказательства, версии исходников,
идентификаторы заданий и SHA-256 экспортов — в
[отчёте](stepa-t1-t4-evidence-2026-10-19.json).

`gemma-4-31b`: два реальных запроса через VK→GenAPI. HTTP 500 от VK, затем
по одному платному запросу на пакет. Сервис корректно завершил ожидание через
220 секунд и сохранил расчётный резерв. GenAPI завершил задачи только через
452,40 и 450,82 секунды (`runtime` провайдера). Оба поздних ответа прошли полный
валидатор локально; они не использованы для подмены неуспешного живого замера.
Первый использовал полный формат ответа, второй — сокращённый. Расход этих двух
задач: 0,5758 + 0,5641 = 1,1399 ₽.

Проверена также уже поддерживаемая `gemma-4-26b`: при 7000 токенах ответ обрезан
(`finish_reason=length`, около 94 секунд). Отдельно проверены штатные 14000 токенов
и две попытки: первый ответ снова обрезан, повтор прерван общим таймаутом редактуры.
Последующая проверка провайдера подтвердила `finish_reason=length` и для повтора.
Обрезанный ответ не принимается даже при HTTP 200. Все пять платных задач
завершились; суммарная стоимость по самим задачам — **4,208 ₽**, остаток счёта —
60,79 ₽. Смена границ двухдесятичного баланса по интервалу отдельного прогона может
включать запоздалое списание другой задачи, поэтому расход взят из сверки ID.
Успешной живой приёмкой 26B не объявлена. Настройка модели по умолчанию не изменена.

в отчёт попадают только числовые значения баланса.
