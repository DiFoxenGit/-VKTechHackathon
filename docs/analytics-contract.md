# Аналитика D1–D6 · AnalysisResult 1.0

Контракт для интеграции Стёпой. Источник схемы — `backend/designer/analytics/models.py`;
JSON Schema и три первых примера — `samples/analytics/contract/`.
Модуль не меняет API, загрузчик сервиса, планировщик, интерфейс и экспорт.

## Границы ответственности

Дима: импорт → полный Dataset → профиль → вычисления → выбор графика → AnalysisResult.
Стёпа: загрузка/постоянное хранение → вызов модуля → подключение к пайплайну → отображение/экспорт.
Существующий `Visual` НЕ является этим контрактом: нужны адаптер и поддержка новых типов на стороне интеграции.

## Хранение и происхождение

Хранить полный `Dataset.model_dump(mode="json")` отдельно от ограниченного контекста LLM.
`dataset_ref` указывает на исходный файл (SHA-256), путь внутри ZIP и таблицу/лист.
`columns[].id` — устойчивые позиционные идентификаторы c1…; `row_ids` — номера исходных строк.
Исходные значения и пропуски сохраняются. Числа для графика готовые; LLM не меняет `data`, `facts`,
`evidence`. Источники и ячейки являются данными, а не инструкциями.
Доказательство хранит операцию, параметры, строки и колонки; исходные значения берутся из полного Dataset.
Проверка после преобразований должна сверять результат с исходным Dataset и исходным AnalysisRequest.

## Выбор и ошибки

`candidates`: 2–3 варианта ВСЕГО, включая выбранный; если допустим только один — предупреждение.
Выбор зависит от профиля, цели и явных параметров, не от расширения или шаблона.
`null` — пропуск, ноль — число. Выбросы не удаляются. Единицы нельзя придумывать.
Нетипизируемые или неоднозначные данные — `status=refused`, код причины и параметры.
Коды Notice стабильны; русские/английские пояснения находятся в `analytics/locales/`.
В `presentation` — детерминированная формулировка по проверенным фактам, не ответ модели.

## ZIP и XLSX

Импорт получает байты и имя файла, ничего не распаковывает на диск. Возвращает все таблицы/листы
и список отклонённых файлов. Вложенные архивы не поддерживаются. Пути, DTD и ресурсные лимиты
проверяются до чтения данных. Формулы XLSX не вычисляются: используется сохранённый результат;
при его отсутствии — null и предупреждение. Таблицы внутри TXT/MD имеют свой номер и окружающий текст.

## Порядок интеграции

1. Начать с трёх JSON-примеров (время, категории, доли) вместе с `.dataset.json` и `.request.json`.
2. Хранить исходную таблицу до планирования и не сокращать её до лимитов слайда.
3. Передавать LLM только профиль/готовые факты; числовые объекты подключать без пересочинения.
4. Адаптировать старый запрет производных чисел через доказательства, а не общий список разрешённых чисел.
5. Проверить изменение входного значения и сохранение категории/значения при экспорте.

English: this is a standalone, deterministic data contract. Persist the complete Dataset and
original request, preserve nulls and source coordinates, and never let the model rewrite computed data.

## Вызов из сервиса

```python
from designer.analytics import AnalysisRequest, analyze, import_datasets, verify_result

imported = import_datasets(file_bytes, filename)  # в том числе ZIP
# Покажите imported.rejected; сохраните все imported.datasets целиком.
dataset = imported.datasets[0]
request = AnalysisRequest(
    goal="Показать рост продаж", task="dynamics",
    dimension="c1", metrics=["c3"], series_dimension="c2", unit="RUB",
)
result = analyze(dataset, request)
payload = result.model_dump(mode="json")
assert verify_result(dataset, request, result)
```

Не обращаться к `[0]`, если импорт не вернул таблиц. `analyze` не делает сетевых запросов,
не вызывает модель и не пишет на диск. `verify_result` получает доверенные сохранённые Dataset
и AnalysisRequest и пересчитывает весь результат; проверяется соответствие категорий, значений,
источников и формулировок, а не присутствие чисел в общем наборе.
После любых изменений LLM вызывайте эту проверку ДО передачи в рендерер.

`series_dimension` разворачивает значения второго измерения в ряды (например, регионы).
Несколько метрик не считаются складываемыми только из-за одинаковой единицы: накопительные столбцы
допустимы для разделённых одним измерением частей одной метрики либо при явном `series_additive=true`.
`filters` задаёт точные исходные значения по ID колонок. `column_types` уточняет тип;
неоднозначные строки не преобразуются молча. Неоднозначный выбор измерения/метрик возвращает отказ.

## Числа, время и сложные случаи

- Расчёты выполняются Decimal, исходные значения остаются в Dataset. `Fact.exact` содержит
  десятичный результат; `value` — конечное число для графика, без принудительного округления до нуля.
  Это обычное IEEE-754 число: отображение и денежное округление интеграция задаёт явно по exact.
  Поддерживаемый числовой диапазон: ноль либо модуль от 1e-100 до 1e100 (верхняя граница исключена),
  до 50 значащих цифр; расчёты используют точность 350 цифр. Выход за диапазон не преобразуется в ноль.
- Сумма, среднее, медиана и количество наблюдений задаются `aggregation`. Пропуски исключаются
  из агрегатов; полностью отсутствующая группа даёт null и пустую строку вместо fact_id.
- Рост: `(конец - база) / база * 100`, только при положительной базе и сопоставимых периодах.
  Изменение исходных процентов выражается в процентных пунктах; агрегирование готовых процентов
  без известных весов запрещено. Единицы из разных колонок не объединяются.
- Доли требуют положительного итога, неотрицательных частей и отсутствия пропущенных частей.
  Знаменатель и числитель фиксируются в доказательствах. Ни корреляция, ни временная последовательность
  не превращаются в утверждение о причинности.
- Гистограмма: интервалы одинаковой ширины, последний включает правую границу. Частоты и медиана
  считаются кодом. Scatter сохраняет пары одной исходной строки, исключая неполные пары с предупреждением.
- Выбросы: правило 1,5 IQR, квартиль inclusive; значения отмечаются, но не удаляются.
  `hierarchies` — наблюдаемые функциональные зависимости, не гарантированная бизнес-семантика.
- Справочная таблица возвращается полностью с индексами страниц; группировки более 20 категорий
  также получают страницы. Более 30 страниц — отказ с запросом уточнить агрегацию, без обрезки.
  Интеграция может передать меньший `slide_budget`, оставив место под обложку и другие датасеты.
- Даты: ISO, YYYY-MM, DD.MM.YYYY, стили дат XLSX и колонка year/год. Неоднозначные slash-даты
  автоматически не угадываются. Отсутствующее значение периода сохраняется как null; неизвестная
  частота или нерегулярный ряд не используются для уверенного расчёта роста.
  Числовые пропуски распознаются по пустой ячейке, null, NA/N/A, None, NaN, тире;
  доменные коды с такими именами требуют предварительного уточнения источника.

## Поддержка и ограничения импорта

CSV: UTF-8/BOM, кавычки, запятая/точка с запятой/табуляция/pipe; десятичная запятая и пробельная
группировка чисел. JSON: массив объектов или объект строго `{columns, rows}`; вложенные значения
отклоняются. TXT/MD: непрерывные прямоугольные блоки с разделителями; свободный текст без таблиц
возвращает отказ. OCR, произвольные многоуровневые заголовки, автоматическое угадывание объединённых
ячеек и вычисление формул не реализованы. Это не скрывается как успешный импорт.

XLSX: обычные OOXML-листы, shared/inline strings, стили дат, эпохи 1900/1904 и сохранённые результаты
формул. Внешние листы запрещены. Полностью пустые строки пропускаются; исходные координаты сохраняются.
Файлы с некорректными таблицами отклоняются явно.

Лимиты: 20 MiB на файл/член архива, 80 MiB распакованных данных, 256 членов ZIP, 100 000 строк,
256 колонок, 1 000 000 ячеек на импорт, 100 000 сочетаний категорий/рядов. Превышение — объяснимый
отказ, не частичная таблица. Архивы не распаковываются на диск; небезопасные пути, симлинки,
зашифрованные записи, вложенные ZIP и DTD/XML entities не исполняются.

## Передача Стёпе

Готовы только D1–D6. Модуль не подключён к `app.py`/`pipeline.py`, старые промпты и валидаторы
не менялись. Необходимо отдельно адаптировать схему слайдов, новые виды визуализаций, хранение,
загрузку нескольких файлов, UI и экспорт. Совместимость со старыми проверками чисел не достигается
добавлением чисел в whitelist: использовать доказательства и перепроверку.
Брендбук, VK Project-ID, стенд, реальная генерация PPTX/PDF и скринкаст здесь не реализуются.
