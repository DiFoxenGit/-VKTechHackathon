## 1. Стенд

**http://158.160.225.35** — именно `http`, домена и сертификата нет.

Модель, три шаблона кейса и проверка содержания уже подключены: ничего настраивать не
нужно. Версия сценария видна в шапке («Воркфлоу 1.12.0») и по адресу
`http://158.160.225.35/api/v1/workflow`.

Путь по интерфейсу:

1. **Главная «О чём расскажем?»** — вставить бриф в большое поле.
2. **«Материалы»** под полем — загрузить файл с фактами (из `samples/source/`).
3. **«Настроить»** — выбрать шаблон, количество слайдов (3–20), «Для кого» и «Задача
   презентации», нажать **«Готово»**.
4. **«Создать презентацию»** — модель строит структуру, открывается экран
   **«Сначала — главное»**: заголовки и тезисы можно править, слайды — двигать,
   добавлять и удалять.
5. **«Сверстать варианты»** — экран **«Одна история. Три взгляда»**: классический,
   выразительный и минималистичный варианты уже свёрстаны, переключение мгновенное.
6. **«Открыть редактор»** — слайды, правка текста, **«Просмотр»** (страница, отрисованная
   сервером), **«Настроить → Проверка слайдов»** (находки аудита и кнопка «Исправить»).
7. **«Скачать»** — PPTX, PDF или HTML.

Задача занимает **1,5–3,5 минуты**: план колоды моделью, три варианта вёрстки,
проверка содержания моделью и экспорт (замер 29.09 на трёх шаблонах: 95–194 с на
сервере). Первая задача после перезапуска сервера дольше: он заново разбирает шаблоны.

## 2. Сценарии

Материалы лежат в репозитории: [samples/source/](../samples/source/).

### Сценарий 1. Защита инициативы перед руководством

| Поле | Значение |
|---|---|
| Материалы | `samples/source/материал-инициатива.md` |
| Шаблон | `VK Tech шаблон` |
| Слайдов | `10` |
| Для кого | `Руководство` |
| Задача презентации | `Представить идею` (назначение «инициатива») |

Бриф:

```
Защита инициативы перед руководством: предложить сервис автоматической вёрстки презентаций, показать эффект пилота в цифрах и попросить решение о запуске на всю компанию.
```

Что должно получиться: три варианта одной колоды, цифры на слайдах — только из
материала (186 минут, 74 минуты, 19 из 42, 68 колод, 1 400 рублей), сравнение «186 минут
вместо 4» — нативной диаграммой. Если модель всё же напишет число, которого нет в
материале, аудит отметит его в панели «Проверка слайдов».

### Сценарий 2. Тот же материал на другом шаблоне

Повторить сценарий 1, поменяв в «Настроить» только шаблон — сначала на
`Шаблон презентации VK Education`, потом на `VK_WorkSpace_Клиентская_конференция_Шаблон_03`.
Текст тот же, а палитра, гарнитуры, поля и страницы-прототипы — из файла шаблона.
Так видно, что дизайн-система берётся из PPTX, а не зашита в код.

### Сценарий 3. Незнакомый шаблон

**«Настроить» → «Загрузить свой»** принимает любой `.pptx` до 50 МБ. Сервис разберёт
гарнитуры, шкалу кеглей, палитру, поля, направляющие и роли страниц; карточка шаблона
покажет, сколько страниц-прототипов и цветов найдено. Имён макетов в коде нет — именно
это проверяют на финале. Для проверки подойдёт шаблон ЛЦТ 2026 или любой свой.

### Сценарий 4. Продукт вместо инициативы

От назначения зависит состав слайдов: у продукта появляются рынок, ценность для
сегментов и отличия от альтернатив. В интерфейсе назначение выбирается пунктом
«Задача презентации» (`Представить идею` → инициатива, `Показать результаты` → проект);
продукт и фичу проще запустить через API — см. раздел 3 с материалом
`samples/source/материал-продукт.md` и `"purpose": "product"`.

### Свои материалы

Принимаются `.txt`, `.md`, `.csv`, `.json`, `.docx`, `.pptx`, `.pdf` с текстовым слоем
(сканы без текста — нет), а также `.zip` с картинками и SVG для визуального пакета.

### На что смотреть

| Где | Что проверять |
|---|---|
| «Сначала — главное» | структура до вёрстки; правки уходят в вёрстку как есть, модель повторно не вызывается |
| «Три взгляда» | одна структура разложена по-разному: вертикально, в две колонки, с акцентом |
| «Просмотр» в редакторе | страница, отрисованная сервером: ровно то, что уйдёт в файл; «Показать замечания» подсвечивает находки |
| «Проверка слайдов» | находки правил и модели; у исправимых — «Исправить», сервис пересобирает слайд новой ревизией; «Проверить содержание» и «Проверить по изображению» вызывают модель отдельно |
| «Воркфлоу 1.12.0» в шапке | версии агентов, файлы промптов, sha256 и причина каждого изменения |
| Скачанный PPTX | открыть в PowerPoint и щёлкнуть по тексту: он редактируется, диаграмма — диаграмма, таблица — таблица; ни одного слайда-картинки |

Готовые результаты тех же сценариев — в [samples/](../samples/README.md): девять колод
(три шаблона × три варианта) в PPTX, PDF и HTML с полными отчётами аудита.

## 3. Через API

Тот же пайплайн без интерфейса. Swagger на публичном стенде выключен; контракт —
в [API.md](API.md) и [openapi.json](openapi.json).

```bash
BASE=http://158.160.225.35/api/v1

# 1. Загрузить материал — в ответе id контент-пакета
curl -s -F "file=@samples/source/материал-продукт.md" $BASE/content-packs

# 2. Список шаблонов — выбрать id
curl -s $BASE/templates

# 3. Запустить генерацию: план, три варианта, аудит, экспорт
curl -s -H "Content-Type: application/json" $BASE/generations -d '{
  "template_id": "<id шаблона>",
  "brief": "Представить платформу видеовстреч продуктовому комитету и попросить решение о переводе компании",
  "purpose": "product", "language": "ru", "slide_count": 12,
  "content_pack_ids": ["<id пакета>"], "contextual_audit": true
}'

# 4. Дождаться задачи: status = completed, в presentation_ids — три варианта
curl -s $BASE/jobs/<id задачи>

# 5. Презентация с отчётом аудита и ревизией
curl -s $BASE/presentations/<id презентации>

# 6. Файлы
curl -s -o deck.pptx "$BASE/presentations/<id>/export/pptx?revision=<ревизия>"
curl -s -o deck.pdf  "$BASE/presentations/<id>/export/pdf?revision=<ревизия>"
curl -s -o deck.html "$BASE/presentations/<id>/export/html?revision=<ревизия>"
```

`purpose` — `initiative`, `project`, `product` или `feature`. Всё это одной командой
делает сборщик эталонов:

```bash
python tools/make_samples.py http://158.160.225.35 --output out/check --require-chart
# свой шаблон и свой материал:
python tools/make_samples.py http://158.160.225.35 --template new.pptx --source notes.md --brief "..." --output out/unseen
```

Он сохраняет PPTX/PDF/HTML всех вариантов, полные отчёты в `evidence/`, `report.json`
(время, ошибки, предупреждения, хеши файлов) и `run.json`.

## 4. Локальный запуск

### Docker — рекомендуемый способ

Нужны Docker с Compose и шаблоны кейса (файлы организаторов в репозиторий не
коммитятся).

```bash
git clone <адрес репозитория> && cd <папка>
cp .env.example .env
# в .env: DESIGNER_LLM_BASE_URL, DESIGNER_LLM_MODEL, DESIGNER_LLM_API_KEY;
# для проверки по картинке — DESIGNER_VLM_MODEL
mkdir -p templates && cp /путь/к/шаблонам/*.pptx templates/
docker compose up -d --build
```

- интерфейс — http://localhost:3000, API — http://localhost:8000;
- при старте сервис импортирует все `.pptx` из `templates/`; первый старт занимает пару
  минут — разбор шаблонов и замер их фона;
- модель — любая OpenAI-совместимая: vLLM, инференс VK или облачный API. Проверенная
  конфигурация и ограничения по лицензиям и размеру — в [MODELS.md](../MODELS.md),
  переключение на профиль VK — в [deploy.md](deploy.md#переключение-на-vk).

Без ключа модели работает всё, кроме планирования: шаблон загружается и разбирается,
колода собирается по готовой структуре — `POST /api/v1/generations` с полем `outline`.

### Без Docker

Бэкенду нужен Python 3.11 и LibreOffice (для PDF и HTML), фронтенду — Node 20+.

```bash
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r backend/requirements.txt
cd backend && uvicorn designer.server:app --port 8000 --workers 1
```

```bash
cd frontend
cp .env.example .env                              # VITE_API_URL=/api/v1
npm ci && npm run dev                             # http://localhost:5173
```

Запросы к `/api` vite проксирует на `VITE_DEV_API_PROXY` (по умолчанию
`http://localhost:8000`) — чтобы смотреть интерфейс против стенда, укажите там его адрес.

Развёртывание на сервере, автодеплой, откат и домен — [deploy.md](deploy.md).

## 5. Тесты

Те же проверки, что в CI на каждый push и pull request.

### Бэкенд — pytest

```bash
pip install -r backend/requirements.txt pytest
cd backend && pytest -q
```

205 сценариев (в CI 196 проходят, 9 пропускаются без файлов организаторов): разбор шаблонов, вёрстка трёх вариантов, аудит и исправления, экспорт и
проверка нативности PPTX, генерация с подменённой моделью, API, безопасность загрузок.
Сценариям с реальными шаблонами нужны файлы в `templates/` (или путь в
`DESIGNER_TEMPLATE_DIR`), конвертация — LibreOffice; без них эти сценарии пропускаются.
Ответы модели в тестах подменяются: проверяется обработка ответов, а не качество модели.

### Фронтенд

```bash
cd frontend
npm ci
npm test          # юнит-тесты node:test
npm run build     # проверка типов tsc и production-сборка
```

### Регресс вёрстки без модели

План колоды фиксированный, поэтому различия объясняются только шаблоном. Подходит для
любой папки с `.pptx`, в том числе для незнакомых шаблонов:

```bash
python tools/bench_templates.py templates --outline tools/regress_outline.json --sheets out/
```

Контакт-листы всех слайдов и метрики по записанному PPTX; как читать результат —
[regression.md](regression.md).

### Живой прогон с моделью

```bash
python tools/make_samples.py http://localhost:8000 --require-chart
```

Три шаблона × три варианта с проверкой содержания; завершается ошибкой, если есть
ошибки аудита, задача дольше пяти минут или в наборе нет ни одного нативного графика.

### CI

GitHub Actions на зеркале `DiFoxenGit/-VKTechHackathon`: этап **Tests** — `pytest`,
`frontend` (тесты, типы, сборка, образ), `Integration` (регресс вёрстки в боевом образе с
LibreOffice); после них **Deploy** на стенд при push в `main`.

## 6. Если что-то не так

| Симптом | Что это и что делать |
|---|---|
| Страница не открывается | открывать `http://158.160.225.35` без `https` |
| «Модель не вернула корректный ответ» | открытая модель на 20B иногда не справляется с материалом; повторить запуск |
| Слайдов меньше, чем просили | материала не хватило: сервис делает меньше честных слайдов вместо слайдов с водой и пишет об этом в задаче |
| В «Проверке слайдов» ошибка «факт не содержится в источнике» | контекстный аудит поймал утверждение модели без опоры на материал — исправить текст в редакторе |
| Долгая первая задача после перезапуска | сервер разбирает шаблоны и измеряет их фон один раз при старте |
| Локально нет PDF или HTML | не установлен LibreOffice (в Docker-образе он есть) |
