# Восстановление модельной генерации и API истории

## Подтверждённые причины

- В задании `7f5c9ca8a9674dd6bb6dc075dfa8ede0` VK трижды ответила HTTP 200, но прислала диаграмму без `steps`. После-валидатор Pydantic проверял требование, однако оно отсутствовало в передаваемой модели JSON-схеме. Промпт также не объяснял контракт `steps`.
- Транспортный резерв GenAPI работал при тайм-ауте/5xx/неразбираемом JSON. Валидный JSON с неверной схемой или фактами повторно отправлялся только VK; на резерв этот случай не переключался.
- `GET /presentations?limit=1` сначала вызывал `Store.list` для всей истории: все сохранённые документы с исходниками и аналитическими доказательствами загружались и разбирались до пагинации. В ответ также попадала тяжёлая аналитика. На auto-sell воспроизводились тайм-ауты истории в 8–30 секунд; отдельно лёгкие `/workflow` и `/templates` отвечали HTTP 200 за 0,41–0,52 секунды. Это не отказ модели. Произвольную серверную консоль auto-sell ограниченный deploy-ключ не предоставляет; дополнительные безопасные показатели собираются штатным преддеплойным скриптом.

## Изменения

1. JSON-схема условно требует непустой `steps` для process/icon/cycle/pyramid/timeline; промпт содержит пример. Сервер продолжает отклонять неподдержанные данные: шаги не выдумываются и не подставляются автоматически из произвольных тезисов.
2. VK остаётся основной. При повторной невалидности последняя попытка существующего бюджета используется для настроенного резерва. При бюджете из трёх попыток это максимум две VK и одна GenAPI. Успешное исправление VK не вызывает резерв. GenAPI проходит тот же валидатор фактов/формата; повторной платной отправки после невалидного резерва нет. Транспортный тайм-аут уже принятого задания также не повторяет POST.
3. История использует SQL COUNT/LIMIT/OFFSET и удаляет тяжёлые поля до JSON-декодирования. `analysis`, `analysis_results`, `business_proof`, `sources`, `deck`, `audit` доступны по прежнему полному GET конкретной презентации; исходники и доказательства не удаляются. Порядок, общее количество и ревизии сохраняются.
4. Преддеплойная диагностика выводит только количества/размеры записей и HTTP-статусы локальных API. Она не выводит ключи, заголовки авторизации или содержание документов. CI после деплоя проверяет шаблоны и страницу истории, а не только `/health`.

`generation.inference.provider/model` и `generation.actual_inference` показывают фактического провайдера. Историческое поле `inference.fallback_used` обозначает переход к непроверенному расчётному тексту; успешный проверенный ответ резервной модели остаётся модельным содержанием, а не расчётным резервом. Для причины переключения по валидации сохраняется `provider_fallback_reason=invalid_response`.

## Проверка

Регрессии без внешних оплат: условная схема диаграмм, переключение после невалидных VK-ответов, отсутствие оплаты при успешной VK, запрет повторной оплаты невалидного GenAPI, сохранность следов валидации, SQL-пагинация без чтения записей вне страницы, сохранность полного документа, безопасная диагностика и прежние проверки резервного транспорта. Живой статус после доставки фиксируется отдельным отчётом; тестовый транспорт не называется реальным вызовом провайдера.
