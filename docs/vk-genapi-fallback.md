# Текстовый инференс: VK → GenAPI

Первым для каждого текстового вызова остаётся VK `qwen38-27b-fp8`. Явно настроенный резерв — Gemma 4 31B через GenAPI. Это другая модель: точной Qwen из VK в проверенном каталоге GenAPI нет.

Gemma 4 имеет открытые веса под Apache 2.0, вариант 31B содержит 30,7B параметров и укладывается в ограничение ТЗ до 35B. Источник: [официальная карточка Google](https://huggingface.co/google/gemma-4-31B-it). Доступ подтверждён коротким реальным JSON-запросом 19 октября 2026. OpenAI-совместимый proxy GenAPI эту модель не принимает; используется [родной endpoint Gemma 4](https://gen-api.ru/model/gemma-4/api).

```dotenv
DESIGNER_LLM_PROVIDER=vk
DESIGNER_VK_MODEL=qwen38-27b-fp8
DESIGNER_VK_API_KEY=<секрет VK>
DESIGNER_VK_PROJECT_ID=<проект VK>
DESIGNER_VK_TIMEOUT=20
DESIGNER_FALLBACK_PROVIDER=genapi
DESIGNER_FALLBACK_MODEL=gemma-4-31b
DESIGNER_FALLBACK_API_KEY=<секрет GenAPI>
DESIGNER_FALLBACK_MAX_TOKENS=14000
DESIGNER_FALLBACK_TIMEOUT=150
```

Адрес VK берётся из выданного quickstart. Адрес GenAPI зафиксирован адаптером. Старые `DESIGNER_LLM_*` сохраняются для ручного отката, но автоматически не вызываются. Image-настройки независимы от текстового резерва.

Резерв включается при HTTP 408/429/5xx, сетевой ошибке или непригодном ответе VK. При успехе VK платный резерв не вызывается. Ошибки 400/401/403/422 и неполная конфигурация не маскируются. Каждый следующий вызов вновь начинает с VK: восстановление основного провайдера не требует переключения настроек.

GenAPI получает одну задачу с `is_sync=true`, без `callback_url`, с JSON-ответом и низким бюджетом рассуждений. Если возвращён асинхронный ID, результат опрашивается без повторного POST. Общий таймаут ограничен; после таймаута задача может продолжать выполняться у провайдера. Общий агентный цикл по-прежнему может сделать новый вызов при нарушении схемы: каждый такой вызов оплачивается отдельно.

Фактически ответивший провайдер и модель сохраняются в `generation.actual_inference`; поля выбранного основного провайдера сохраняют прежний смысл. Логи не содержат ключей и тел ошибок. Работа через резерв не доказывает доступность VK: для проверки основного инференса нужен успешный прямой ответ VK.
