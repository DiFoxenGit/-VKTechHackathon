## Что делать дальше, по приоритету

### 1. Довести интерфейс до API
Экраны структуры, вариантов и аудита пока используют локальный движок `engine.ts`. Клиент (`src/services/api.ts`) и сопоставление типов готовы: осталось перевести экраны на `presentationService.generate`, показывать три варианта с сервера, подсвечивать проблемы аудита по координатам и скачивать экспорт по ссылкам API. Локальный движок остаётся только предпросмотром.

### 2. Устойчивость к ответу модели
`generation.py` возвращает 502 на первом же невалидном JSON. Нужны повтор с напоминанием схемы и мягкая починка ответа: на открытых моделях 20–35B такие ответы будут регулярными.

### 3. Нарезка контент-пакета
Сейчас весь материал (до 120 000 символов) уходит в промпт целиком. На модели с окном 32k это не поместится. Нужны разбиение на фрагменты и подбор релевантных под каждый слайд.

### 4. Подбор макета под смысл слайда
`layout.py` берёт паттерны по кругу: `best[i % len(best)]`. Нужен скоринг: роль слайда против роли паттерна, вместимость текста, наличие визуализации, штраф за повтор соседей.

### 5. Подгонка текста по метрикам шрифта
Высота строк оценивается по числу символов, отсюда формулировка «текст может не поместиться». Замер по реальным метрикам уберёт целый класс дефектов вёрстки.

### 6. Контекстный аудит по изображению
Приложение 1 требует проверок по картинке слайда. Превью уже рендерится, нужен VLM с открытыми весами и разбор ответа в те же коды проблем.

### 7. Задача со звёздочкой
Text-to-image до 20B, промпт из темы слайда и палитры шаблона, вставка в слот без искажения пропорций, проверка на посторонний текст на картинке.

### 8. Мелочи, заметные жюри
- Версия у каждого промпта, а не одна на манифест.
- Варианты пока отличаются только раскладкой; стоит развести и плотность.
- HTML-экспорт отдаёт текст кривыми: для поиска по тексту нужен отдельный рендер.
