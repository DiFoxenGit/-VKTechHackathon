## Явные периоды

```python
from designer.analytics.business_periods import BusinessPeriods
from designer.analytics.business import build_business_analysis, verify_business_analysis

settings = BusinessPeriods(
    current=('2026-04', '2026-06'),
    previous=('2026-01', '2026-03'),
    year_ago=('2025-04', '2025-06'),
    history=('2025-01', '2026-06'),
    plan=('2026-01', '2026-12'),
)
analysis = build_business_analysis(sales, plan, products, regions, settings=settings)
assert verify_business_analysis(sales, plan, products, regions, analysis, settings=settings)
```

Периоды не выбираются из данных/эталона/даты компьютера. Старый вызов без settings
сохраняет согласованные периоды по умолчанию. Каждый запрос имеет собственный
неизменяемый объект: параллельные вызовы не меняют глобальное состояние.

Включены целые закрытые ISO-месяцы. Отчётный период — от 1 до 12 месяцев;
previous такой же длины и заканчивается до current; year_ago — те же месяцы годом
ранее. История/план имеют явно заданное покрытие, до 120 месяцев. Требуется полное
зерно каждой таблицы; частичный месяц и недостающие ключи не подставляются нулями.
previous не обязан быть непосредственно предыдущим периодом: человеческие подписи
показывают конкретный диапазон, а не обещают QoQ для любого выбора.

Исторические ID `q3_net`, `qoq_net_growth` и подобные сохранены для интеграции.
Теперь это машинные имена: значения относятся к settings.current/previous; реальные
диапазоны лежат в Fact.period и analysis.period_settings. Формулы и отображаемые
подписи не должны трактовать эти ID как неизменно III квартал 2026.

settings нужно сохранить как доверенный запрос и передать при проверке. Нельзя
извлекать доверенные параметры из изменённого результата. Подмена настроек/чисел
обнаруживается полным пересчётом. Настройки не добавлены в интерфейс/API сервиса:
их подключение остаётся у Стёпы/Андрея.

## Контекст без фиксированных предложений и заголовков

```python
from designer.analytics.business_story import build_business_story, verify_business_story

story = build_business_story(analysis, text, conditions=conditions_json)
assert verify_business_story(analysis, text, story, conditions=conditions_json)
```

Новый явный контракт: `ContextConditions` в `business_conditions.py`, JSON Schema
в `samples/business-acceptance/period-context-v1/conditions.schema.json`.
Он содержит восемь смысловых частей текста, бюджет, инженеров, аналитиков,
максимум параллельных внедрений, ответственных и при необходимости событие канала.
Заголовки и формулировки прозы произвольны: вместо догадки о смысле передаются
проверяемые значения и точные цитаты текущего источника. Для числовой цитаты
требуется одно согласованное значение; поддержаны цифры с пробелами и перечисленные
русские формы чисел 0–10. Отчётный диапазон явно указан ISO-месяцами в своей цитате.

Цитаты и разделы должны присутствовать в текущем тексте. Несовпадение, неоднозначность
или значение без подтверждающей цитаты — объяснимый отказ. Старые условия не
подхватываются автоматически из story.conditions при проверке; нормализованный контракт
сохраняется как отдельный доверенный вход. Доказательства включают цитату и символьные
координаты; хеш относится к каноническому тексту, byte-SHA файла сохраняет сервер.

Бюджет проверяется на сумму потолков/резерва. Ограничения мощности отражаются в
рисках и критериях действий. Если любой ресурс равен нулю, действие по внедрению получает
`capacity_status=no_capacity_reported`, а не обещание выполнимого внедрения.
Положительное число ресурсов означает `requires_capacity_review` для внедрения; для финансового/регионального анализа мощность внедрения не оценивается. По этим данным
нельзя вычислить производительность команды или обещать число запусков.
Роли в действиях берутся из подтверждённых условий. Источник события канала
может отсутствовать: тогда соответствующая гипотеза не публикуется.

Даты действий — концы следующих трёх календарных месяцев после current.end;
это календарные контрольные точки, не обещание ровно 90 суток. В основной истории
приведены выбранные периоды, текущий бюджет, мощности и сроки, а не старые строки шаблона.

Старый текстовый вход без conditions поддерживается для исходного периода через
явную ограниченную грамматику бюджета и ресурсов. Она читает мощности из текущего
текста, неоднозначную/неподдержанную формулировку отклоняет. Для другого периода
нужен новый контракт с подтверждённым отчётным диапазоном: старый контекст Q3
нельзя незаметно использовать как согласованное решение для Q2.

Это **не универсальное извлечение бизнес-условий из любого текста** и не доказательство
смысловой непротиворечивости всей прозы. Нормализация утверждается автором/проверяющим.
Противоречия вне объявленных цитат/условий требуют содержательной проверки, а не скрытого NLP.
