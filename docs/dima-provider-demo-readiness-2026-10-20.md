## D1: режимы и рекомендация

Проверены первичные источники GenAPI 20 октября:
[очередь](https://gen-api.ru/docs/queue),
[синхронные запросы](https://gen-api.ru/docs/synchronous-requests),
[параметры Gemma 4](https://gen-api.ru/model/gemma-4/api).
Долгие запросы идут через очередь, результат получается по ID. У Gemma есть `is_sync`;
по умолчанию `false`. Sync удерживает соединение до ответа, документация рекомендует
его для коротких задач. Это не доказательство ускорения полного бизнес-запроса.
Подтверждённого быстрого профиля Gemma или SLA для нашего payload не найдено.

Случай «три зависли, две проходили» — наблюдение команды, не доказанный hard limit.
Оставляем `DESIGNER_MAX_JOBS=2` и `DESIGNER_FALLBACK_TIMEOUT=220`. Compose теперь
передаёт лимит заданий и использует тот же таймаут 220, что Python и `.env.example`.
Это локальный семафор одного backend, не общий лимитер аккаунта: два стенда, image-
запросы и другие клиенты разделяют бюджет и очередь. Демо стендов не запускать
одновременно ради нагрузочного теста. Число 220 — предел ожидания клиента, не SLA:
ВК, планирование, изображения и экспорт могут добавить время сверх него.

Оставляем async: один POST, затем GET раз в 2 с. При таймауте сохраняется task ID
текстовой задачи; перед новой платной отправкой следует проверить прежнюю по GET.
Автоповтора POST после транспортного сбоя нет. Исторические замеры резерва:
[короткий JSON 8,632 с / полный пакет 121,243 с](stepa-genapi-limited-2026-10-19.md).

Вопрос для поддержки, если понадобится подтверждение квоты: «Каковы общие и
помодельные лимиты одновременных задач нашего аккаунта для gemma-4-31b и z-image?
Общий ли пул очереди, что означает processing без списания дольше четырёх минут,
есть ли гарантии приоритета/ускорения sync для полного JSON-запроса?»
Сообщение поддержке автоматически не отправлялось; ключ в обращение не включать.

## D3: контракт для Стёпы

Подключать существующий `designer.ai.draw_image` / `ai_assets.generate_illustrations`;
параметры провайдера остаются на backend. Не вызывать GenAPI из браузера.
План и размещение: [model-image-plan.md](model-image-plan.md).
Машинный пример транспорта и результата сервиса:
[z-image-contract.json](../samples/provider-contracts/z-image-contract.json).
Это структурный пример с условным ID/URL, не новый оплаченный результат.

Транспорт: `POST https://api.gen-api.ru/api/v1/networks/z-image`,
`Authorization: Bearer <закрытый image-ключ>`. Поле `callback_url` отсутствует,
поскольку явный null ранее дал HTTP 422. Одна задача, `model=turbo`, одна PNG,
8 шагов, guidance 0, 1024×1024, перевод/расширение промпта выключены.
Затем `GET /api/v1/request/get/{request_id}`; `processing` не означает ошибку.
PNG скачивается без Authorization, только с разрешённого HTTPS-хранилища,
без редиректов, не более 20 МиБ. Общий image-таймаут адаптера 150 с.

Ошибки 401/403 — проверить ключ, 422 — параметры; сетевой сбой, failed/error и
таймаут не вызывают повторного платного POST. При таймауте задача может продолжать
работать у провайдера. Сервис сохраняет презентацию и честный image-статус:
`unavailable`, `failed`, `partial`, `ready` или `not_requested`. Ошибка плана останавливает
платные вызовы до их отправки. Частичный успех сохраняет count/requested_count.
Для трёх оформлений используется один набор изображений. Числа и диаграммы не рисуются
моделью изображений. Поля provider body и ключи в UI/диагностику не передаются.

Живое доказательство: 26,305 с до готовности трёх вариантов с двумя фотографиями,
включая планирование 2,735 с. Из оставшихся 23,570 с нельзя вычитать «чистую стоимость
картинок»: туда также входят основной текст и сборка. Дополнительных платных картинок
для искусственного повторения доказательства не создавалось. Изолированный image-
тайминг / парный прогон с замороженным содержанием остаётся отдельным замером.
Локальный отчёт: `output/model-image-plan-acceptance/report.json`, рядом шесть экспортов.

Для демо с запрошенными изображениями **включаем их ожидание в таймер 300 с**:
от принятия генерации до готовности вариантов с фактическими картинками. Экспорт PDF
показываем отдельным временем; для общей проверки «до скачанного PDF» добавляем его
к сквозному времени. Не переносим картинки за таймер ради красивого результата.
Этот короткий прогон не заменяет S8/S9 на полном бизнес-запросе.
