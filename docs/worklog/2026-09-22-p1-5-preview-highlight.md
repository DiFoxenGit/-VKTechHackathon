# P1-5. Подсветка замечаний в просмотре слайда

**PR:** feat/p1-5-preview-highlight · **Автор:** DiFoxen + Claude · **Дата:** 2026-09-22

## Проблема

Сервер умеет обводить найденные проблемы прямо на слайде:
`GET /presentations/{id}/slides/{index}/preview?highlight=true` дорисовывает к SVG красные
рамки с текстом находки в `<title>`. Интерфейс запрашивал превью с `highlight=false`, то
есть самая наглядная часть аудита пользователю не показывалась.

## Что сделано

- В окне просмотра появилась строка с переключателем «Показать замечания» (включён по
  умолчанию) и счётчиком находок текущего слайда: «3 замечания на слайде» с правильным
  склонением, зелёная отметка, когда находок нет, и состояние «Рисуем слайд…» на время
  запроса.
- Переключатель входит в зависимости эффекта, поэтому превью перезапрашивается сразу.
- При смене слайда или переключателя старая blob-ссылка отзывается, а `previewUrl`
  очищается: раньше `<img>` какое-то время показывал уже отозванную ссылку.
- Находки без координат (`fill_ratio`, `source_reference` и подобные) рамкой не
  обводятся — сервер рисует только те, у которых есть `box`. Чтобы включённый
  переключатель не выглядел сломанным, счётчик в таком случае прямо говорит: «без
  привязки к месту, текст в панели проверки». Для этого в `AuditIssue` добавлено поле
  `boxed` (в API оно уже было — `box`).

## Проверка

- `npx tsc --noEmit`, `npm run build` — чисто;
- на стенде `158.160.225.35`, колода `aa8e1d1a…`, слайд 10 (`word_break`): с включённым
  переключателем на схеме видна красная рамка и счётчик «3 замечания на слайде», с
  выключенным — чистый слайд;
- сверено с сервером: `preview?highlight=true` отдаёт SVG на 304 байта больше и содержит
  `fill="red" … stroke-width="2"`, при `highlight=false` этого нет.
