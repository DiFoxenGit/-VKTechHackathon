# Переезд на SourceCraft

**Ветка:** chore/sourcecraft-migration · **Автор:** DiFoxen + Claude · **Дата:** 2026-09-22

## Зачем

Репозиторий переезжает в SourceCraft (`lct-hackaton-2026/case-14-ai-presentation-designer-team-7`,
приватный), GitHub после переноса архивируется. Вместе с кодом переезжают проверки и
автодеплой: CI на GitHub Actions заменяется рабочим процессом SourceCraft.

## Что сделано в репозитории

- `.sourcecraft/ci.yaml` — рабочий процесс `ci`: задания `pytest`, `frontend`,
  `integration` идут параллельно, `deploy` объявлен через `needs` и стартует только после
  трёх зелёных. Триггеры: push в `main` и предложения изменений в `main`.
- `.sourcecraft/branches.yaml` — политики ветки по умолчанию: прямой push, force-push и
  удаление закрыты, изменения идут через предложения.
- Основная ветка теперь `main`, как в созданном организаторами репозитории; приёмник
  деплоя и фильтры CI переведены на неё. История с GitHub вмержена в `main` с сохранением
  их первого коммита, а README организаторов с условием кейса лежит в
  [`docs/case.md`](../case.md) — в корне остался README нашего решения.
- `.github/workflows/` удалён.
- `docs/deploy.md`, `docs/regression.md`, `deploy/ci-receive.sh` — описание CI и деплоя
  переписано под SourceCraft.

## Чем CI отличается от прежнего

| | GitHub Actions | SourceCraft |
|---|---|---|
| Окружение | боевые Docker-образы собирались в CI | образ кубика + те же команды установки, что в `Dockerfile` |
| Фронтенд | сборка образа `frontend` целиком | `npm ci && npm run build` (тот же `tsc -b && vite build`) |
| Кеш между запусками | кеш слоёв и pip | нет, зависимости ставятся заново |
| Отчёт регресса | markdown в сводке джобы | печатается в лог, файлы и контакт-листы — артефакты кубика |
| Лимиты | 20–30 минут на джобу | кубик 20 минут, задание час, три рабочих процесса в запуске |

Сборку Docker-образов SourceCraft внутри кубиков не делает (только через кубики
совместимости с GitHub Actions и внешний реестр), поэтому проверка «образ собирается»
из CI ушла: её по-прежнему делает сам деплой на сервере.

## Доступы

- Репозиторий приватный, deploy-ключей уровня репозитория в SourceCraft нет, поэтому
  сервер читает код по HTTPS с персональным токеном, ограниченным этим репозиторием и
  ролью просмотра. Токен лежит в `~/.git-credentials` (права `600`), в remote URL его нет.
- Для деплоя выпущен отдельный ключ ed25519: приватная половина — секрет `DEPLOY_SSH_KEY`
  в SourceCraft, публичная — в `authorized_keys` сервера с `restrict,command=` на приёмник.
  Прежний ключ GitHub Actions остаётся в `authorized_keys` до конца переезда, потом его
  нужно убрать.
- У токена есть дата истечения: когда она подойдёт, деплой встанет на `git fetch`, пока
  токен не перевыпустят.

## Грабли переезда

Приёмник на сервере переустанавливается командой `cat > ~/vk-designer-ci/receive.sh` с
рабочей копии. На Windows файл лежал с CRLF, и сервер ответил
`/usr/bin/env: 'bash': No such file or directory`. Чтобы это не повторилось, добавлен
`.gitattributes`: `*.sh`, `*.yaml`, `*.yml` и `Dockerfile` всегда забираются с LF.

## Проверено

- сервер забирает код с SourceCraft по HTTPS с токеном: `git fetch origin main` проходит;
- деплой прогнан тем же путём, которым его зовёт CI (`ssh -i <ключ> ... "deploy <sha>"`):
  образы пересобраны, `/health` ответил через 3 секунды, на сервере коммит `5986560`.
