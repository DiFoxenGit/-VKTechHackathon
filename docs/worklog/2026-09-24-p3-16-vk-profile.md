# P3-16: подготовка профиля инференса VK

**PR:** [#37](https://github.com/DiFoxenGit/-VKTechHackathon/pull/37) · **Автор:** Codex · **Дата:** 2026-09-24 · **База:** `ba4364e` · **Ветка:** `codex/p1-7-p3-16`

## Проблема
Смена провайдера требовала замены URL, ID модели и ключа. Параметры запроса
и таймаут были фиксированы; профиль невозможно было переключить одной строкой.

## Что изменено
`designer/inference.py` выбирает целиком openai или vk; транспорт `ask` остаётся
общим. Настраиваются лимит ответа, таймаут и JSON mode. Docker передаёт профиль
и его настройки; health и метаданные колоды используют выбранную модель.
VLM сохраняет явные настройки и использует выбранный профиль только как fallback.
В `.env.example`, `MODELS.md`, `docs/deploy.md` описаны конфигурации, запуск и откат.
`tools/check_inference.py` проверяет реальный API и, опционально, генерацию через
сервис, три экспорта PPTX, модель, аудит и время менее пяти минут.

## Проверки
14 контрактных тестов: маршрутизация запроса и ключа, таймаут, JSON mode,
неполный профиль без fallback, валидация настроек, VLM override, health и откат.
Полный `pytest -q -rs` в изолированном `.venv`: **134 passed, 10 skipped**.
Пропуски связаны с отсутствием исходных шаблонов и LibreOffice. Первый запуск
в глобальном Python обнаружил конфликт пакета `tests` с соседним проектом;
в чистом окружении зависимостей репозитория ошибок нет.
`docker compose config --quiet` и `git diff --check` проходят.

## Ограничение и следующий шаг
**P3-16 не закрыта полностью:** тестовый ключ, URL и точный API ID VK не предоставлены.
Реальные квоты, поддержка полей и полный прогон за пять минут не подтверждены.
Публичные сведения о других провайдерах не использованы как контракт VK.
После получения доступа выполнить команды из `docs/deploy.md`, сохранить отчёт
с job ID и временем, проверить PPTX глазами. Производственный стенд не переключался.
