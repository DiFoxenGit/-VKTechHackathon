## Слияние работы команды (P0-1 аудита)

**Проблема.** Кода было три версии. SourceCraft `main` (он же стенд) — `1bf6691`. GitHub
`main` — всё это плюс P2-10…P2-14: Андрей мерджил PR в `master` на зеркале и вливал его в
`main`. GitHub `master` — ещё и PR #37 (P1-7, P3-16, приёмка P1-4…P1-8). Деплой коммитов
команды падал: сервер принимает только то, что есть в `origin/main` SourceCraft. Из-за
этого на стенде жил уже исправленный баг — пустой список «Мои презентации» при 50 колодах
на сервере.

**Что сделано.** Одним предложением изменений в SourceCraft влит GitHub `master`, затем —
пустым по содержимому слиянием — коммит `c3b6d35` из GitHub `main`, чтобы зеркало
сливалось без конфликтов и запускало проверки. Конфликты были только в документах:
`MODELS.md` сохраняет и генерацию изображений, и профиль инференса VK; `gap-analysis.md`
взят в редакции команды с фактами о P3-15. `docs/plan-to-win.md` снова убран из
репозитория — зеркало публичное, а план просили не хранить в git; скриншоты прогонов
браузера (`output/`) — в `.gitignore`.

**Проверено.** pytest — 157 passed, 9 skipped; регресс на 4 шаблонах — 0 ошибок,
предупреждений 18 против 66 на прежнем стенде; CI на зеркале зелёный; стенд на `6192b3b`.

**Договорённость.** Основная ветка — `main` в SourceCraft. Сначала push туда, потом в
GitHub `main`; PR в GitHub `master` больше не открываем.

## Быстрые исправления

- **Устаревшие тексты.** Экран шаблонов обещал «демоверсию», которая «извлечёт палитру…
  полный перенос требует бэкенда», хотя шаблон разбирается целиком. Тост после загрузки
  шаблона тоже занижал, что сделано.
- **Склонения.** «3 макетов», «22 цветов», «5 шаблона», «2 слайдов». Все числа в интерфейсе
  идут через общий `plural`/`count` (`frontend/src/plural.ts`) с юнит-тестами на
  `node:test`; тесты запускаются в CI на Node 24 без зависимостей.
- **Чужие презентации.** После PR #37 список «Мои презентации» берётся с сервера, а
  учётных записей нет — любой посетитель увидел бы все колоды. Теперь браузер помнит id
  колод, созданных в нём (`slide-studio:own`), и показывает только их.
- **Архивы.** Поправка к аудиту: защита от zip-бомбы уже была — `check_zip` отклоняет
  архив больше 300 МБ в распакованном виде, а Python не распакует файл больше
  заявленного размера. Добавлены лимит на один файл (100 МБ) и на коэффициент сжатия
  (больше 200 — отказ), а отказ по размеру архива приходит 413 с причиной вместо общей
  ошибки разбора.
- README: в схеме «Аудит — 26 правил» → «38 кодов находок».
