# P1-6. Проверки моделью вызываются из интерфейса

**PR:** feat/p1-6-audit-buttons · **Автор:** DiFoxen + Claude · **Дата:** 2026-09-22

## Проблема

`POST /presentations/{id}/audit?contextual=true|visual=true` умеет звать агента `audit`
(по тексту) и `audit_image` (по картинке слайда, одиннадцать вопросов Приложения 1). В
интерфейсе запустить их было нельзя: проверки шли только внутри генерации, а панель
«Проверка слайдов» показывала результат детерминированных правил и подпись «потребует
серверного аудита». То есть самая заметная часть работы агентов пользователю не
предъявлялась.

## Что сделано

**Интерфейс**

- В панели проверки — две кнопки: «Проверить содержание» и «Проверить по изображению».
  На время запроса обе выключены, у нажатой крутится индикатор; по окончании — тост с
  числом замечаний.
- У находки видно, кто её нашёл: детерминированные правила помечаются молча, у находок
  модели появляется подпись «Модель, по тексту» или «Модель, по изображению». Для этого в
  `AuditIssue` добавлено поле `origin`, которое выводится из `category` и `element_id`.
- Повторный запуск не плодит дубли: сервер каждый раз собирает отчёт заново, и интерфейс
  заменяет список находок целиком, а не дописывает к нему.

**Бэкенд**

- `run_audit` теперь доливает в отчёт проверки самого файла (`merge_file_issues` по
  сохранённому `export_check`). Без этого нажатие кнопки молча теряло находки, которые
  видны только в pptx: `file_broken`, `raster_slide`, `branding_moved`, `chart_labels`.
- Убран дубль функции `merge_file_issues` — она была объявлена в `audit.py` дважды.

## Тесты

- `test_rerun_audit_keeps_file_level_findings` — после `POST /audit` находка `raster_slide`
  остаётся и в ответе, и в сохранённом отчёте;
- `pytest -q` на сервере: 121 passed, 9 skipped (пропуски — тесты, которым нужен
  LibreOffice; в CI они выполняются).
